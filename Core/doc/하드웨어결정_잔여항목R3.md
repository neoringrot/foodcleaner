## 0. 현재 상태 요약

R1 회로 기준으로 **핀맵·.ioc·펌웨어 골격 동기화는 완료**됐다. CubeMX generate 반영,
드라이버/인터페이스 계층까지 수정 완료(빌드 정합 확인, 실컴파일은 CubeIDE에서 필요).
아래는 그 위에서 **하드웨어 값/극성/정책을 확정해야 코드가 실동작으로 완성**되는 잔여 항목이다.

### 이미 확정되어 반영 완료된 결정 ✅
| 결정 | 반영 위치 |
|---|---|
| PF8/PF9/PF10 = **입력**(TIMER-OUT, HALL-INT1/2) | `gpio_ctrl` EXTI, `stm32f1xx_it.c` |
| PF2~PF5 = **도어 홀센서**(바이메탈 아님) | `gpio_ctrl` GPIO_EXTI_[TW]HALL_[OPEN/CLOSE] |
| LIFT = **TIM4 HW PWM**(PB8/PB9, 20 kHz) | `lift_motor.c` DRV8871 핸들 |
| 클럭 **HSI 유지** / 도어-EN = **PE3·PE4**(PD01 리맵 폐기) | `main.h` `o_EN_DOOR_TRASH`=PE3, `o_EN_DOOR_WATER`=PE4 |
| Hall 확장기 = **U24 0x3B, HS1~HS8**, INT=PF9 | `hallsensor.c`, `tca9554.h` |

### 1-1. DC 전류센싱 — **RESOLVED [2026-08-09]** (R1 NET 추적 + 모터 데이터시트)
> ✅ 채널↔모터 매핑·션트·게인·환산·임계 모두 확정, `dc_current.c/.h` 반영 완료.

- **채널↔모터 매핑 (R1 NET: op-amp IN+ 션트 → DRV8871 → IN핀 TIM채널 역추적)**

  | ch | ADC핀 | op-amp | DRV8871 | 모터 |
  |---|---|---|---|---|
  | `DC_CURR_LIFT` | PC5/IN15 | U4 | U6 | 리프트 |
  | `DC_CURR_TDOOR` | PB0/IN8 | U5 | U9 | 쓰레기도어 |
  | `DC_CURR_WDOOR` | PB1/IN9 | U25 | U11 | 급수도어 |

- **센싱 체인 (3채널 동일)**: 10mΩ 션트(WSHP2818R0100) → LM321LV 비반전 게인 **×2**(1+1K/1K) → 470Ω+1nF RC → ADC. **= 20mV/A**(≈24.8 code/A, ≈40.3mA/code)
- **모터 `JK30ZYT-5840-577`**(24VDC, 감속비577): 무부하 0.2A / **정격 1A** / **구속 4.5A**
- **트립 임계**: `DC_CURRENT_TRIP_MA = 3000`(3.0A, 정격+인러시 위, 구속 아래) → 걸림감지. 코드환산 ≈74. 필요시 헤더 상수만 조정
- **검산**: 1A→1007mA, 4.5A→4512mA(오차 <2%)
- **주의(잔여, 벤치)**: ① 분해능 coarse(40mA/code) — median-of-5로 완화, 스톨감지엔 충분 ② PWM(20kHz) 중 전류 chopping 리플 존재 → median 필터로 완화, 필요시 샘플수↑ ③ 각 op-amp 게인저항(U5:R162, U25:R166) GND쪽 1K 대칭 가정(U4는 R158=1K 확인) — 벤치 실측 권장
- **연계 시나리오**: `사용자_시나리오_검토정리R3.md` §5.2 "모터 부하량 체크 및 걸림 해소"
- **남은 것(정책)**: 과전류 검출 시 정지/역회전/재시도 시퀀스 → §3-2 참조

## 2. 벤치 확인 필요 — 극성/방향 ❓

### 2-1. 도어 리미트 홀 극성 — **RESOLVED [2026-08-10]** (R1 NET 회로 확정)
> ✅ 회로 추적으로 **active-low 확정**, 코드 반영 + 반전 가능하게 매크로화 완료.
- **회로 근거(R1 NET)**: 5개 홀넷 모두 **10K 풀업→3P3V**(R13/R40/R151/R32/R83), 센서 커넥터 3선식(J3: VCC/OUT/GND) = **오픈드레인 홀 → active-low**(자석=LOW). EXTI IT_FALLING이 "리미트 도달 순간"과 일치.
- **반영**: `tdoor.c`/`wdoor.c`의 `AtOpen/AtClose`를 `DOOR_LIMIT_ACTIVE_HIGH`(기본 0=active-low) 매크로 기준으로 정리. 센서 변형 시 **헤더 매크로 한 줄(0→1)** 로 전체 반전.
- 매핑: PF5=T-HALL-OPEN, PF2=T-HALL-CLOSE, PF4=W-HALL-OPEN, PF3=W-HALL-CLOSE
- **추가 인지**: W-HALL-CLOSE(PF3)는 HW NOR 게이트 U13(SN74LVC1G02)로 `Bimetal-80`과도 논리조합(솔더브릿지 경유) — MCU 직접읽기와 별개인 하드웨어 안전 인터록. 용도/소비 확인은 별도(§3 계열).
- **남은 것(벤치)**: 실제 자석 접근 시 LOW 확인(형상/장착), 반대면 매크로만 반전. → [HW미검증_항목R3.md](HW미검증_항목R3.md) 1-1

### 2-2. 도어 회전 방향 — **RESOLVED [2026-08-25]** (리프트는 2026-09-20 확정)
> ✅ 벤치 확정. **두 문의 방향이 서로 반대**이므로 값만 보고 유추하지 말 것.

| 문 | 테스트벤치 | DRV8871 매핑 |
|----|-----------|--------------|
| 배수문 WDoor(U5) | `tb_wdoor_reverse` **0=닫힘 / 1=열림** | **Forward=닫힘** → `wdoor.c`에서 `WDoor_Open()`=`DRV8871_Reverse`로 **스왑 반영** |
| 배출문 TDoor(U7) | `tb_tdoor_reverse` **0=열림 / 1=닫힘** | Forward=열림 (`tdoor.c` 스왑 없음) |

- 스왑은 `wdoor.c`/`tdoor.c` **한 곳**에만 둔다 — 호출부(시나리오)는 계속 `Open()`/`Close()`라는 이름으로 물리 동작을 뜻한다. 방향이 또 바뀌면 이 두 함수만 고치고 시나리오는 건드리지 않는다.
- ⚠️ 스왑 전에는 `WDoor_Open()`이 물리적으로 문을 **닫고** 있었다 → 모음/동작의 배수문 개폐가 반대로 동작하던 상태. 통합 풀런 전 **모음 1사이클 육안 확인** 필요.
- **리프트(U6) ✅ 확정 [2026-09-20]**: 벤치 점동 결과 `tb_lift_reverse` **0=상승 / 1=하강**. `lift_motor.c`의 임시 매핑(`Lift_Up`=Forward=상승)이 **그대로 맞아 스왑하지 않았다** — 배수문(WDoor)만 스왑이 필요했다는 결론. 하강 중 HS8 정지도 관측됨(1-25).
- → [HW미검증_항목R3.md](HW미검증_항목R3.md) §1-2

## 3. 정책/제어 로직 결정 필요 — 접근자만 제공됨 ❓

아래는 하드웨어 인터페이스(읽기/제어 함수)는 완성됐으나, **언제/어떻게 쓸지(제어 정책)**가 시나리오 확정 대기.

### 3-1. 도어 리미트 기반 정지 시퀀스 — ✅ **확정 [2026-08-25]**
- 제공: `[TW]Door_LimitArm()` + `[TW]Door_Reached{Open,Close}()` (arm 이후 EXTI 하강엣지 **OR** 현재 레벨 → 스쳐 지나가도 인식). 순수 레벨은 `At{Open,Close}()`.
- ✅ **구동 프로파일 확정** — 테스트벤치(`tb_drv8871`)와 시나리오(`moeum.c`/`dongjak.c`)가 **동일 값·동일 규칙**. 수치는 `wdoor.h`의 `WDOOR_*`, `tdoor.h`의 `TDOOR_*` 한 곳에만 둔다.

  | 이동 | duty | 종료 조건 |
  |------|------|-----------|
  | 배수문 열림 | 80 %로 2 s 기동 → 65 % 유지 | WHALL-OPEN 인식, 미인식 대비 **6 s** 상한 |
  | 배수문 닫힘 | 80 % 고정 | **4.2 s** 경과가 정상 종료(그 전 WHALL-CLOSE 인식 시 즉시) |
  | 배출문 열림/닫힘 | 80 % 고정 | THALL 인식 후 **1 s 추가회전**(래치) 뒤 종료, 방향별 **14.3 s** 하드 상한 |

- 열림 duty는 `WDoor_OpenDutyAt(el)`을 **매 tick 재지령**해야 킥→유지 전환이 걸린다.
- ⚠️ **실패처리는 없다**: 시간 상한 도달도 "정상 종료"로 처리하므로 도어 관련 `DJ_ERR_*` / `MOEUM_ERROR` 낙하 경로가 사라졌다. 고장 판정이 필요하면 `dj_wdoor_done()`/`dj_tdoor_done()`이 종료 사유(리밋/시간)를 구분해 반환하도록 확장할 것 → **잔여 결정 항목**.
- 연계: `사용자_시나리오_검토정리R3.md` §4.2(배출), §4.3(수거통 확인) · [HW미검증_항목R3.md](HW미검증_항목R3.md) §1-2-1

- 연계: §4.2 동작 단계. 상세 현황 = [구현현황_및_미구현_점검R3.md](구현현황_및_미구현_점검R3.md) 2단계 팬 항목.

### 3-4. TIMER_OUT (PF8, 555 타이머 입력) 소비 — ✅ **연동 완료 [2026-08-15 신스펙 항목8]**
- 제공: `gpio_ctrl_exti_flag_get(GPIO_EXTI_TIMER_OUT)`, `gpio_ctrl_exti_read()`
- ✅ **소비처 확정**: 배출문 개방 = HW 2분 타이머 시작 → **TIMER-OUT 하강엣지 = 2분 완료**로 배출 교반을 정지(`dongjak.c` `DJ_DS_EXPEL`). 문 닫기는 별도로 135분(`DJ_T_LATCH_MS`)에 개시.
- ⏳ **남은 것**: **핀 극성·플로팅(NOPULL) HW 미검증** → 현재 SW 2분 백업(`DJ_DISCH_STIR_SW_BACKUP=1`)을 켜 둔 상태. [HW미검증_항목R3.md](HW미검증_항목R3.md) 1-5
- 연계: `사용자_시나리오_검토정리R3.md` §3.2 "기억 레치 릴레이 & 딜레이 타이머"

### 3-5. HS1~HS8(U24) 소비 로직 — **HS1~5 구현 완료 [2026-08-15] / HS6~8 잔여**
- 제공: `HallSensor_Get(0..7)`, `g_hall_mask`, INT 저지연 갱신(`HallSensor_ServiceInt`)
- ✅ **HS1~HS5(마개 위치)**: [mode_arbiter.c](../Scenario/mode_arbiter.c)가 `HallSensor_GetMask() & 0x1F`를 **모드와 무관하게** 100ms마다 디코딩(정확히 1비트만 유효 + 3샘플 디바운스 + 전이 에지) → 모드 전환 / 정지([jungji.c](../Scenario/jungji.c)) 위임. 매핑은 §1-2 표.
> **HS6~HS8은 센서 자체가 ✅HW 검증완료(2026-08-15)** — 아래는 전부 **펌웨어 소비 로직 미구현**이라는 뜻이다(미검증 아님).
- ◐ **HS6 교반원점(가이드)**: R3 5단계에서 소비 시작 — `Devices/guide_edge.c`(엣지 계수, I02) → `Scenario/rinse.c` 준비 탐색 R001~R006(모음·동작 헹굼 전, 가이드 감지 즉시 정지) · `rotation_port.c` 헹굼 엣지 계수. 회전수 운전 위치원은 FG(`BldcCtrl_Position`). **배출 전 교반날 각도 정렬(홈잉) 여부는 여전히 미결정.**
- ❌ **HS7 수거통 유무**: 현재 `DJ_BIN_CHECK`는 처리횟수(`cycle_count`)+분말높이(거리센서 fill%)만 본다. **수거통이 빠져 있어도 배출로 진행**하므로, 이 채널을 `dj_bin_check`에 물려야 안전판정이 완성된다. ← **안전 공백, 우선순위 높음**
- ◐ **HS8 리프트 하단**: 리프트 하강 정지 리미트. **2026-09-20 벤치 계층 소비 착수 + 동작확인(§0.18·§0.18.5)** — 드라이버에 `Lift_AtBottom()`(HS8 제품 디코드)을 두고 `tb_lift`가 **하강 방향 한정**으로 자동정지(`tb_lift_limit_stop`, 5 ms 확인). 벤치에서 `limit_hit` 래치까지 확인됐다. **시나리오 소비는 여전히 없다** — 리프트 기능 자체가 C071 미정의.
  > **상단 리미트는 회로에 없다**(REV02 넷리스트 확인). 리프트 위치 센서는 HS8 하나뿐이라 **상승은 시간 상한으로만 끝난다**. 상단 검출이 필요해지면 J16/PF7 `NEW-HALL-INT`(현재 미배정, 용도 N9 회신 대기 — 가이드 홀 추정) 또는 `DC_CURR_LIFT` 스톨 검출이 후보다.
- **잔여 확정 필요값(벤치)**: ~~`MODEARB_CONFIRM_SAMPLES=3`(300ms)~~ → ★2026-09-21 **10(≈1.0s)** 으로 상향(실제 위치만), 이탈/이중인식은 `MODEARB_LOST_CONFIRM_SAMPLES=3`(300ms) 유지 — 마개를 천천히 돌릴 때 통과 위치(HS3 정지/HS4 배수) 오트리거 대응. 조작감 벤치 확인 잔여.
