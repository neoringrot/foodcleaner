# U21(W25Q128) 음성 플래시 구조 — 설계서 v1

> **작성** 장형동 · 2026-09-20 · 검토서 [R3_변경범위_검토R3.md](R3_변경범위_검토R3.md) §13 · 착수 4단계(C085·C086)
> **대상 부품** U21 = **W25Q128JVSIQ** (16 MB, 256 B 페이지 / 4 KB 섹터 / 64 KB 블록), SPI1 16 Mbit/s (Mode 0, 8-bit, NSS 소프트, CS = PC4 `o_SPI1_EEPROM_CS`), /WP·/HOLD = SB21/SB22로 3P3V 풀업.
> **입력** `doc/R3/3_개발사 전달 녹음파일(필수 안내)/` WAV 26종 (44.1 kHz · 16-bit · mono · 총 7.76 MB)
> **표** [`doc/R3/U21_음성플래시_구조.xlsx`](../../../../doc/R3/U21_음성플래시_구조.xlsx) — 슬롯 맵 · 디렉터리/헤더 바이트 맵 · 파일별 블록 · 재생 경로
> **원칙** 가장 큰 파일 기준 **고정 크기 슬롯**. 슬롯 = 64 KB 블록의 정수배라 파일 하나 = 블록 이레이즈 N회로 갱신.

## 1. 플래시 맵 (16 MB)

```
0x000000 ┌───────────────────────────┐ 블록 0  섹터 0     디렉터리 (4 KB)              §2
0x001000 │                           │ 블록 0  섹터 1~15  예약 — 보정값/설정 후보 (60 KB)
0x010000 │                           │ 블록 1~3           예약 (192 KB)
0x040000 ├───────────────────────────┤ 슬롯 0   (4 블록)  ID 0  01-01 배수 타임 시작     §3·§5
0x080000 │ 슬롯 1                    │ ID 1  01-02 배수 타임 끝
0x0C0000 │ 슬롯 2                    │ ID 2  02-01 모음 시작
   ⋮     │  …  256 KB × 32           │  ⋮
0x800000 │ 슬롯 31                   │ ID 31 예비
0x840000 ├───────────────────────────┤ 예약 (7.75 MB) — 2차 언어 / 44.1 kHz 업그레이드 / 로그
0xFFFFFF └───────────────────────────┘
```

주소 공식: `SLOT_BASE(n) = 0x040000u * (n + 1)`, `SLOT_DATA(n) = SLOT_BASE(n) + 0x100`, `SLOT_END(n) = SLOT_BASE(n) + 0x3FFFF`.
블록 번호(64 KB 단위) = `SLOT_BASE(n) >> 16` = `4(n+1)` … `4(n+1)+3`.

## 2. 디렉터리 — 0x000000, 섹터 0 (4 KB)

리틀 엔디언. 0xFF로 채운 빈 섹터 = "디렉터리 없음".

| 오프셋 | 크기 | 필드 | 값 | 설명 |
|---|---|---|---|---|
| 0x000 | 4 | `MAGIC` | `'Z' 'G' 'V' 'C'` (0x4356475A LE) | 디렉터리 매직 |
| 0x004 | 2 | `VERSION` | 0x0001 | 구조 버전 |
| 0x006 | 2 | `SLOT_KB` | 256 | 슬롯 크기 KB |
| 0x008 | 1 | `SLOT_COUNT` | 32 | 슬롯 수 |
| 0x009 | 1 | `ENTRY_SIZE` | 16 | 엔트리 크기 B |
| 0x00A | 2 | `SAMPLE_RATE` | 16000 | Hz |
| 0x00C | 1 | `BITS` | 12 | 유효 비트 |
| 0x00D | 1 | `CHANNELS` | 1 | 모노 |
| 0x00E | 2 | `RESERVED` | 0xFFFF | — |
| **0x010 + 16·n** | **16** | **엔트리 n (n = 0..31)** | | 슬롯 n = 음성 ID n |
| ↳ +0 | 4 | `START_ADDR` | `SLOT_BASE(n)` | 슬롯 시작(헤더 포함) |
| ↳ +4 | 4 | `DATA_LEN` | 바이트 | PCM 길이. **0 = 빈 슬롯** |
| ↳ +8 | 4 | `DATA_CRC32` | | PCM 데이터 CRC32(IEEE) |
| ↳ +12 | 1 | `ID` | n | 음성 ID (= 슬롯 번호) |
| ↳ +13 | 1 | `FLAGS` | bit0 VALID · bit1 ERROR(에러 안내) · bit2 RESERVED_GAP(결번) | |
| ↳ +14 | 2 | `DUR_10MS` | 재생 시간 / 10 ms | 타임아웃·UI용 |
| 0x210 | 4 | `DIR_CRC32` | | 0x000~0x20F CRC32 |
| 0x214~0xFFF | | 0xFF | | |

부팅 시: `MAGIC`·`DIR_CRC32` 검사 → 실패면 **슬롯 헤더 32개를 순회해 디렉터리를 RAM에서 재구성**(플래시는 건드리지 않음) → 그것도 실패면 음성 비활성 + 비프 폴백(`LM4871_Beep` 2회). 기기 동작은 계속된다.

> **현 구현(2026-09-21)**: 위 부팅 검사·복구는 **미구현**이다. `voice.c` 는 디렉터리를 읽지 않고, 재생 때마다 슬롯 헤더만 `Voice_Probe()` 로 본다(매직 `ZGVF`·ID·`DATA_LEN`). 디렉터리 검증은 벤치 `tb_voice_dir_once` 뿐이다.

## 3. 슬롯 헤더 — `SLOT_BASE(n) + 0x000`, 첫 페이지 (256 B)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x00 | 4 | `MAGIC` | `'Z' 'G' 'V' 'F'` |
| 0x04 | 1 | `ID` | 음성 ID (= n). 디렉터리와 불일치면 무효 |
| 0x05 | 1 | `FLAGS` | 디렉터리와 동일 |
| 0x06 | 2 | `VERSION` | 0x0001 |
| 0x08 | 4 | `SAMPLE_RATE` | 16000 |
| 0x0C | 4 | `DATA_LEN` | PCM 바이트 (≤ 261,888) |
| 0x10 | 4 | `SAMPLES` | = DATA_LEN / 2 |
| 0x14 | 4 | `DATA_CRC32` | |
| 0x18 | 4 | `DUR_MS` | |
| 0x1C | 4 | `SRC_HASH` | 원본 WAV md5 앞 4 B — 어떤 녹음에서 만들었는지 추적 |
| 0x20 | 160 | `TEXT[160]` | 멘트 UTF-8, NUL 종료 (최장 멘트 ≈ 130 B) |
| 0xC0 | 56 | `SRC_NAME[56]` | 원본 파일 식별 ASCII (`"02-03"` 등) |
| 0xF8 | 4 | `RESERVED` | 0xFFFFFFFF |
| 0xFC | 4 | `HDR_CRC32` | 0x00~0xFB CRC32 |
| **0x100** | ≤ 261,888 | **PCM** | uint16 LE, 0~4095, 16 kHz. 끝은 0xFF(미프로그램) |

## 6. 변환 규칙 (호스트 도구 `tools/voice_image.py`)

1. WAV 읽기 → 44.1 kHz s16 mono 확인(스테레오면 평균).
2. 리샘플 44,100 → 16,000: `scipy.signal.resample_poly(x, 160, 441)` (다상 FIR, 자동 안티앨리어싱). 길이 = `ceil(n × 160/441)`.
3. 정규화: 피크가 −1 dBFS를 넘으면 스케일 다운(클리핑 방지). 올리지는 않는다.
4. 12-bit 변환: `u12 = clamp((s16 + 32768) >> 4, 0, 4095)` → `uint16 LE`.
5. 헤더(§3) 작성 → CRC32 → 슬롯 이미지(256 B + PCM, 나머지 0xFF).
6. 출력: `voice_image.bin`(0x000000~0x83FFFF, 8.25 MB, 디렉터리 포함) · `voice_slot_NN.bin`(슬롯별) · `voice_table.h`(아래 §7 테이블 자동 생성) · `voice_manifest.csv`.
7. 결번/예비 슬롯은 헤더에 `FLAGS.RESERVED_GAP=1`, `DATA_LEN=0`.

> **실구현(`src/voice_updater/vu_image.py`)은 위와 다르다**:
> 1. 모노가 아니면 변환을 거부한다(평균 안 냄), 16-bit 만 받는다.
> 2. 리샘플은 **선형보간**(scipy 없음·안티앨리어싱 없음), 길이 = `floor(n × 16000/rate)`.
> 3. 정규화 단계 없음.
> 6. 출력은 `--dry-run` 시 `slot_NN.bin`(헤더+PCM) + `directory.bin`(532 B) 뿐이다. 전체 `voice_image.bin`·manifest 는 만들지 않고, 테이블은 `--gen-table` 로 **`voice_table.c`** 만 생성한다(§7.1).
> 7. 결번/예비 슬롯은 **헤더를 쓰지 않는다**(0xFF 유지 — 펌웨어 BEGIN 이 `data_len = 0` 을 거부). 디렉터리 엔트리에만 `FLAGS = GAP`, `DATA_LEN = 0`, `DATA_CRC32 = 0xFFFFFFFF`.

### 7.2 구조체

> **현 구현과의 차이**: enum 은 아래와 같다(`voice_table.h`, 손 관리). `voice_desc_t` 는 실제로
> `{ uint8_t id; uint8_t flags; uint16_t dur_10ms; const char *src; const char *text; }`(§7.1 참고)다.
> 플래시 상 구조체(`voice_dir_*_t`·`voice_slot_hdr_t`)는 **어디에도 정의돼 있지 않다** — 펌웨어는
> 오프셋 상수(`voice.c` `HDR_O_*`)로, 호스트는 `struct.pack_into`(`vu_image.py`)로 읽고 쓴다.

```c
/* voice_table.h — 생성 파일 */
typedef enum {
    VOICE_DRAIN_START = 0, VOICE_DRAIN_END, VOICE_MOEUM_START, VOICE_MOEUM_LID_OPEN, VOICE_MOEUM_DONE,
    VOICE_DONGJAK_START, VOICE_RSV_HEAT_START, VOICE_RSV_GRIND_START, VOICE_BIN_MISSING, VOICE_DISCHARGE_DONE,
    VOICE_SELFCLEAN_START, VOICE_SELFCLEAN_END,
    VOICE_E_GUIDE, VOICE_E_STIR_SPEED, VOICE_E_PIN_CAM, VOICE_E_WDOOR_CLOSE, VOICE_E_WDOOR_OPEN, VOICE_E_DISCHARGE_LOCK,
    VOICE_E_M_STIR, VOICE_E_M_WDOOR, VOICE_E_M_TDOOR, VOICE_E_M_GRIND, VOICE_E_M_LIFT, VOICE_E_M_STEP1, VOICE_E_M_STEP2, VOICE_E_M_FAN,
    VOICE_RSV_26, VOICE_E_FILL, VOICE_E_RINSE_COUNT, VOICE_RSV_29, VOICE_RSV_30, VOICE_RSV_31,
    VOICE_COUNT = 32
} voice_id_t;

#define VOICE_SLOT_BYTES     0x40000u
#define VOICE_SLOT_BASE(n)   (0x40000u * ((n) + 1u))
#define VOICE_SLOT_DATA(n)   (VOICE_SLOT_BASE(n) + 0x100u)
#define VOICE_DATA_MAX       (VOICE_SLOT_BYTES - 0x100u)     /* 261,888 */

typedef struct { uint8_t id; uint8_t is_error; uint16_t dur_10ms; uint32_t addr; uint32_t len; const char *text; } voice_desc_t;
extern const voice_desc_t g_voice_table[VOICE_COUNT];

/* 플래시 상 구조 (voice.h) — packed, little-endian */
typedef struct __attribute__((packed)) {
    uint32_t start_addr, data_len, data_crc32; uint8_t id, flags; uint16_t dur_10ms;
} voice_dir_entry_t;                                   /* 16 B */
typedef struct __attribute__((packed)) {
    char magic[4]; uint16_t version, slot_kb; uint8_t slot_count, entry_size; uint16_t sample_rate;
    uint8_t bits, channels; uint16_t reserved; voice_dir_entry_t e[32]; uint32_t dir_crc32;
} voice_dir_t;                                         /* 0x214 B */
typedef struct __attribute__((packed)) {
    char magic[4]; uint8_t id, flags; uint16_t version; uint32_t sample_rate, data_len, samples, data_crc32, dur_ms, src_hash;
    char text[160]; char src_name[56]; uint32_t reserved, hdr_crc32;
} voice_slot_hdr_t;                                    /* 256 B */
```

### 7.3 재생 경로

| 요소 | 설정 |
|---|---|
| TIM2 | 기본 타이머, PSC = 3, ARR = 999 → 64 MHz / 4 / 1000 = **16.000 kHz**, TRGO = Update |
| DAC1 CH1 (PA4) | Trigger = `DAC_TRIGGER_T2_TRGO`, `DAC_ALIGN_12B_R`, 출력 버퍼 ON, DMA ON |
| DMA2 Channel 3 | Mem→Periph, Half-word/Half-word, **Circular**, 2048 elements, HT·TC 인터럽트, 우선순위 Medium |
| RAM | `static uint16_t s_pcm[2048]` (4 KB, 핑퐁 각 1024 = 64 ms) + 태스크 스택 512 words(2 KB). 디렉터리 캐시는 없다(§2) |
| 태스크 | `Voice_Task`(freertos.c `osThreadNew`) prio = **Normal**(defaultTask·MotorTask 와 같음), stack 512 words. DMA HT/TC 콜백이 세마포어 → 태스크가 다음 1024 샘플(2 KB)을 SPI로 읽어 빈 반쪽에 채움. SPI 2 KB @16 Mbit/s ≈ 1.1 ms ≪ 64 ms |
| 시작 | `LM4871_Enable()`(SD LOW) → 5 ms 세틀 → 반쪽 2개 선채움 → `HAL_DAC_Start_DMA` → `HAL_TIM_Base_Start(TIM2)` |
| 끝 | 마지막 블록 뒤를 2048(중간값)으로 채움 → 다음 HT/TC에서 `HAL_DAC_Stop_DMA` → `HAL_TIM_Base_Stop` → DAC = 2048 → 20 ms 뒤 `LM4871_Disable()` |
| 폴백 | 디렉터리 무효 / CRC 불일치 / 빈 슬롯 → 재생 안 함 + `LM4871_Beep()` 2회(기존 블로킹 비프, 160 ms). 로그 `g_voice.last_err`. **현 구현**: 슬롯 헤더 매직/ID/길이만 보고(PCM CRC 대조 없음) 실패 시 조용히 버린다 — 비프 폴백은 미구현(voice.h "폴백") |

### 7.4 우선순위·중복 규칙 (R3 10시트 TB-O01·O02)

- `Voice_Play(id, VOICE_PRIO_NORMAL | VOICE_PRIO_ERROR)`.
- **에러 > 정상**: 정상 재생 중 에러 요청 → 정상 즉시 중단(페이드 없음, 중간값 채움) → 에러 재생.
- 같은 ID 에러가 **같은 상태 진입에서 두 번** 요청되면 무시(진입 시 1회). 상태가 바뀌면 다시 허용. 판정은 호출 측(시나리오)이 `state_since` 변화로 하고, 플레이어는 "재생 중인 ID와 같으면 무시"만 한다.
- 정상 요청이 정상 재생 중 들어오면 **1-deep 큐(최신 것만)**. 에러 큐는 4-deep FIFO.
- `Jungji_StopAll()`은 음성을 끊지 **않는다**(안내는 정지 후에도 나가야 한다). 단 `Voice_Stop()`은 벤치·앱에서 호출 가능.

### 7.5 `.ioc` (검토서 §15 ioc-6~8)

TIM2 활성(Internal clock, PSC 3, ARR 999, TRGO Update) · DAC OUT1 트리거 Timer 2 TRGO · DMA 탭에서 DAC1 → DMA2 Ch3 Circular Half-word · NVIC `DMA2_Channel3_IRQn` 활성. PA4·SPI1·PC4는 이미 있음.

> **현 구현**: 위 셋은 `.ioc` 에 **반영하지 않았다.** `voice.c` `Voice_Init()` 가 TIM2·DMA2_CH3(NVIC prio 5)을 코드로 잡고, DAC 트리거는 재생 때만 T2_TRGO 로 바꿨다가 끝나면 NONE 으로 되돌린다(비프 경로 유지). `DMA2_Channel3_IRQHandler` 도 `voice.c` 에 있어, 나중에 `.ioc` 로 옮길 때 이 수동 설정과 핸들러를 걷어내야 한다.

## 8. 기록(프로그래밍) 절차 — ~~`tb_voice_load_slot`~~ → **`voiceupdater.*` (2026-09-20 구현완료)**

> **구현 결과가 아래 설계와 다른 점** (§0.14):
> - 로더는 `tb_voice` 가 아니라 **`Core/Devices/EEPROM/voiceupdater.*`** 다(벤치가 아니라 정비 기능).
> - 전송로는 **UART5 · 115200**(UART4 아님). REV02 에 BLE 모듈이 없어 TP6/TP1 유선 직결이다.
> - 청크 체크는 XOR 이 아니라 **프레임 CRC32(zlib 호환)** + 슬롯 전체 CRC32 이중 확인.
> - 슬롯당 블록 이레이즈는 4개 고정이 아니라 **실제 쓰는 만큼만**(`ceil((0x100+len)/64KB)`).
> - 전송량은 8.25MB 가 아니라 **실사용 2.81MB**(빈 슬롯은 보내지 않는다) → 115200 에서 약 4~5분.
> - 호스트 도구는 `src/voice_updater/voice_updater.py`(pyserial 외 의존성 없음).
>
> **→ 실제 규격은 [음성다운로드_프로토콜R3.md](음성다운로드_프로토콜R3.md) 가 정본이다.**

1. 호스트: `voice_image.py --slot N` → `voice_slot_NN.bin`(256 B 헤더 + PCM). UART4(WIFI 포트) 또는 UART5(BLE)로 `VLD <N> <len> <crc32>` 헤더 후 4 KB 청크 전송(청크마다 XOR 체크, ACK/NAK).
2. 펌웨어: 슬롯 N 블록 4개 `BlockErase64` (4 × ~150 ms) → 수신 청크를 256 B 페이지 프로그램(페이지당 typ 0.4 ms) → 전 구간 CRC32 재계산 → 헤더 CRC와 대조 → 디렉터리 엔트리 갱신(섹터 0 이레이즈 + 재기록).
3. 전체 이미지 8.25 MB는 UART 921.6 kbps로 ≈ 90 s. 양산은 **보드 실장 전 외부 프로그래머로 `voice_image.bin` 선기록**을 권장하고, 벤치 로더는 개발·수정용.
4. 디렉터리 섹터는 마지막에 쓴다 — 중간에 전원이 끊겨도 이전 디렉터리(또는 슬롯 헤더 복구)가 살아 있다.
