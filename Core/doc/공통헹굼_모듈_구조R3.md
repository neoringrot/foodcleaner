# 공통 헹굼 모듈 구조 — 설계서 v2 (개정4 회전수 운전 반영)

> ★**v2 [2026-09-21] — R3 개정4(09.21 회전수 운전) 반영.** 교반의 시간 패턴(정3/정지1/역3/정지1)이
> 폐지되고 **"가이드 2회전 + 정지 2 s = 1회 운전"** 으로 바뀌었다(검토서 §17). 이 문서에서 달라진 곳:
> - **§7 `RinseConfig`** — `fwd_ms/stop_ms/rev_ms` 삭제. 교반은 `RotStir_t`(rotation_port) 가 맡는다.
> - **§8** — `dj_stir_alt_tick()` 공용화 계획 **폐기** → 벤더 `rotation.c` + `rotation_port` 로 대체(전면 개정).
> - **§5.3** — cnt 20/40 은 여전히 ⑥ `rinse_lock` 몫. ④ 에서는 **엔진 10회 운전 완료를 임시 종료**로 쓴다.
> - **§11** — 작업 순서에 개정4 ①~④ 를 끼웠다. ①~④ 는 **완료**(구현현황 §0.23~§0.26).

> R3 착수 **5단계**(검토서 §16.1)의 설계서. 2026-09-20 작성.
> 대상 항목: **C006~C011 · C014~C016 · C018~C023 · C060 · C062**
> (C012·C013·C017은 1·2단계에서 이미 반영 완료.)
>
> 관련 문서: 검토서 `R3_변경범위_검토R3.md` §4.2·§4.3·§14 / 구현현황 §0.12·§0.13 /

## 1. 왜 공통 모듈인가 — R2의 복제 현황

| | 모음 (`moeum.c`) | 동작 (`dongjak.c`) |
|---|---|---|
| 회차 수 | 1회 고정 | 2회 고정 **언롤**(`DJ_RINSE1_*`·`DJ_RINSE2_*` 상태 12개) |
| 교반 FSM | `moeum_stir_tick()` + `MoeumStirPhase` 4개 | `dj_stir_alt_tick()` + `stir_phase` |
| 종료 판정 | 사이클 수 `MOEUM_STIR_CYCLES`(18) | 시간 `DJ_RINSE_STIR_MS`(120000) |
| 배수 | `MOEUM_DRAIN_STIR_MS` | `DJ_RINSE1_DRAIN_MS` 30s / `DJ_RINSE2_DRAIN_MS` 90s |
| 급수 | `moeum_fill_on/off` + `MOEUM_FILL_USE_WATER_ON` | `dj_fill_on/off` + `DJ_FILL_USE_WATER_ON` |
| 문 | `moeum_*` WDoor 래퍼 | `dj_wdoor_*` WDoor 래퍼 |

**같은 일을 두 번 쓰고 있고, 종료 판정 방식만 서로 다르다.** 2026-08-26의 §0.8.2("모음과
동작은 종료 방식이 다르다")가 그 증거다. R3는 종료 판정을 **cnt 20/40 하나**로 통일하므로
(C014) 이 분기 자체가 사라진다 — 공통화의 가장 좋은 시점이다.

R3 레퍼런스도 `ZG_R001~ZG_R019` 를 모드와 무관하게 하나로 기술하고 **`ZG_R019` 에서만**
모음(`M001`)과 동작(`D001`)으로 갈린다.

## 3. 인터페이스 — 레퍼런스 `zg_inputs`/`zg_outputs` 의 부분집합

레퍼런스가 헹굼에서 실제로 쓰는 신호만 추린다. **이름을 레퍼런스와 맞춘다** — 훗날 A안으로
갈아타거나 UL1이 생겨도 매핑표가 필요 없게.

```c
/* rinse.h */

/* 관측(읽기 전용). 누가 채우는지는 아래 §4 매핑표. */
typedef struct
{
    /* --- 문 · 물 (실센서) --- */
    uint8_t  drain_open;        /* W-HALL-OPEN  인식       */
    uint8_t  drain_closed;      /* W-HALL-CLOSE 인식       */
    uint8_t  water_level;       /* 수위 감지               */

    /* --- 가이드 (HS6) --- */
    uint32_t guide_edge_count;  /* 누적 엣지 수 (단조 증가) */
    uint32_t guide_last_edge_ms;/* 마지막 엣지 tick        */

    /* --- UL1 상당 (rinse_lock 이 합성) --- */
    uint8_t  hw_water_allowed;  /* 급수 허가. cnt>=20 에서 0 으로 떨어진다 (C019) */
    uint8_t  hw_cycle_complete; /* 회차 완료. cnt>=40                      (C014) */
    uint8_t  hw_stir_fault;     /* 교반 이상 이력 (가이드 미감지/과속/순이동)     */
    uint8_t  stir_fault_reason; /* RinseGuideFault                              */
} RinseInputs;

/* 지령. rinse.c 는 GPIO 를 직접 건드리지 않고 이 구조체만 채운다. */
typedef struct
{
    uint8_t     water;          /* 급수 밸브 ON 요청        */
    uint8_t     water_sensor_supply; /* 수위센서 전원(PE2)  */
    RinseDoor   drain;          /* RINSE_DOOR_HOLD/OPEN/CLOSE */
    uint8_t     stir_dir;       /* 0=정 1=역               */
    uint16_t    stir_rpm;       /* 0 = 정지                */
    uint8_t     error_id;       /* RinseErr (0=없음)       */
} RinseOutputs;
```

> **`rinse.c` 가 액추에이터를 직접 만지지 않는 이유**: 모음과 동작이 같은 물리 자원(WDoor,
> 교반 BLDC, 급수 밸브)을 쓰지만 **소유 태스크와 정지 규칙이 다르다**(`jungji` 가 부하를
> 단일 소유). 지령을 구조체로 돌려주면 호출부(moeum/dongjak)가 자기 문맥에서 적용하고,
> `jungji` 의 정지 규칙도 그대로 유효하다. 이것이 C062("교반 명령만 차단")를 지키는
> 구조적 장치이기도 하다 — 차단은 지령 적용 지점에서 한다.

## 4. 신호 출처 매핑 (REV02 현실)

| 레퍼런스 입력 | R3 문서상 담당 | **REV02 실제** | 이 설계의 공급자 |
|---|---|---|---|
| `guide_edge_count` | 회로(J28→UL1) | 센서만 있음 (HS6 = J28-2 = U24 P5, HW 검증 완료) | `guide_edge.c` — PF9 INT 1ms 서비스 |
| `hw_water_allowed` | UL1이 급수 허가 차단 | **없음** | `rinse_lock.c` — `cnt < 20` |
| `hw_cycle_complete` | UL1 cnt=40 | **없음** | `rinse_lock.c` — `cnt >= 40` |
| `hw_stir_fault` | UL1 이상기억 | **없음** | `rinse_lock.c` — 준비 3회 실패 / 과속 / 순이동 |
| `hw_prepare_ack`·`hw_start_ack`·토큰 | UE1(0x20) 핸드셰이크 | **없음** (UE1 자체가 없음) | **생략.** R007·R012 의 요청/수락 단계는 MCU 내부 상태 전이로 축약 |
| `drain_open`·`drain_closed`·`water_level` | 실센서 | 있음 | 기존 `gpio_ctrl` EXTI |
| UL2 과속(LM2917) | 회로 | **없음** | `rinse_lock.c` — 교반 BLDC FG + 가이드 엣지 간격 (C061, I03 대기) |

> **UE1 핸드셰이크를 생략하는 근거**: 검토서 §0 결론 1 — REV02에 UE1(0x20)이 없다(C001이
> "폐기"로 재판정됨). 레퍼런스 `ZG_R007`·`ZG_R012` 는 `prepare_request`/`start_request` 를
> 내고 `*_ack` + 토큰 일치를 기다리는데, 받을 상대가 없다. 자가세척 진입 판정(C077)도 같은
> 이유로 "MCU 내부 상태로 판정"으로 이미 재정의됐다(xlsx `11_0916변경`).
> **다만 상태는 남긴다** — `RINSE_REQ_PREPARE`/`RINSE_REQ_START` 를 0ms 통과 상태로 두어,
> UE1이 부활하면 대기 조건만 채우면 되게 한다. (C017에서 `*_FILL_EXTRA` 를 0ms로 남긴 것과
> 같은 처리.)

## 5. 상태 기계

### 5.1 `RinseStep`

레퍼런스 R001~R019 와 1:1로 맞춘다(디버깅 시 문서 대조가 쉽도록).

> **현재 코드(1차, §0.27)**: `rinse.h` 에는 준비 탐색 구간만 있다 — `RINSE_IDLE`(0) · `RINSE_PREP_F1`~`RINSE_PREP_F2`(1~5) ·
> `RINSE_PREP_OK`(6) · **`RINSE_PREP_FAULT`(7, E01)**. 아래 설계의 `RINSE_FAULT` 는 준비 실패에 한해 `RINSE_PREP_FAULT` 로 들어갔고,
> R007~R019 회차 상태는 ⑥ 에서 `RINSE_PREP_FAULT` 뒤에 붙는다.

```c
typedef enum
{
    RINSE_IDLE = 0,
    /* --- 준비 탐색 (R001~R006) — 회차 루프 밖, 1회만 --- */
    RINSE_PREP_F1,      /* R001 정회전 탐색, 최대 5s            */
    RINSE_PREP_S1,      /* R002 정지 1s                         */
    RINSE_PREP_R,       /* R003 역회전 탐색, 최대 5s            */
    RINSE_PREP_S2,      /* R004 정지 1s                         */
    RINSE_PREP_F2,      /* R005 정회전 탐색(마지막), 최대 5s    */
    RINSE_PREP_OK,      /* R006 감지 성공 → 회차 진입           */
    /* --- 회차 루프 (R007~R019) --- */
    RINSE_REQ_PREPARE,  /* R007 (UE1 없음 → 0ms 통과)           */
    RINSE_DOOR_CLOSE_C, /* R008 배수문 닫기 명령                */
    RINSE_DOOR_CLOSE_W, /* R009 닫힘 확인 대기                  */
    RINSE_FILL,         /* R010 급수 → 수위 감지                */
    RINSE_FILL_DONE,    /* R011 (추가급수 0초 — C017)           */
    RINSE_REQ_START,    /* R012 (UE1 없음 → 0ms 통과) + 회차시계 기산 */
    RINSE_WASH,         /* R013 본 세척 교반, cnt 20 까지       */
    RINSE_DRAIN_OPEN_C, /* R014 배수문 열기 명령                */
    RINSE_DRAIN_OPEN_W, /* R015 열림 확인 대기 (교반 계속)      */
    RINSE_DRAIN_STIR,   /* R016 열림 후 교반, cnt 40 까지       */
    RINSE_CYCLE_CHECK,  /* R017 완료 조건 검사(과속·이상이력)   */
    RINSE_CYCLE_DONE,   /* R018 done++ (1회만 — C021)           */
    RINSE_NEXT,         /* R019 done < N 이면 R007 로           */
    /* --- 종료 --- */
    RINSE_FINISHED,     /* 호출부가 다음 단계로(모음 M001 / 동작 D001) */
    RINSE_FAULT         /* EX1 등. 교반만 차단, 나머지 유지     */
} RinseStep;
```

**R2 대비 소멸하는 것**: `DJ_RINSE1_CLOSE/FILL/FILL_EXTRA/STIR/OPEN/DRAIN` ×2회분 12개,
`MOEUM_DOOR_CLOSE/FILL/FILL_EXTRA/STIR/DRAIN_OPEN/DRAIN_WAIT` 6개 → `RinseStep` 하나로.

### 5.2 준비 탐색 (C006~C010)

> ✅ **구현 [2026-09-21, 구현현황 §0.27]** — `rinse.h/.c` 1차(`Rinse_PrepBegin/PrepTick`). 모음 `MOEUM_PREP`·동작 `DJ_PREP` 에서
> **시작 직후·급수 전 1회** 호출. 교반 적용은 `RotStir_Manual()`(rotation_port). 벤치 HW 1-33. 회차 루프(R007~)는 아직 호출부에 있다.
> 실제 API: `Rinse_PrepBegin/PrepTick/Reset/GetStep`, 지령은 `RinseOutputs{stir_dir, stir_rpm, changed}`(§3 의 설계 구조체보다 축소),
> 3회 미감지 → `RINSE_PREP_FAULT` → 호출부가 `DJ_ERR_GUIDE`(9)/`MOEUM_ERROR` 로 보낸다(이 시점엔 다른 부하가 안 움직여 전부 정지와 결과 동일).

```
try 1: 정회전 30rpm, 최대 5.000s   ─┐
       정지 1s                      │ 감지되면 즉시 정지 → RINSE_PREP_OK
try 2: 역회전 30rpm, 최대 5.000s    │ (5.000s 정확히 걸리면 감지 우선 — C008)
       정지 1s                      │
try 3: 정회전 30rpm, 최대 5.000s   ─┘
3회 모두 미감지 → hw_stir_fault=1, RINSE_FAULT (E01). **4차 재시도 금지** (C010)
```

- 구간 길이는 `ZG_PREPARE_MS`(5000, 코드 `RINSE_PREP_MS`) / 정지는 `rinse_stop_ms`(1000, 코드 `RINSE_PREP_STOP_MS`) 를 쓴다 — 레퍼런스
  `ZG_R002`·`ZG_R004` 가 `config.rinse_stop_ms` 를 쓴다.
- **`guide_baseline` 방식**: 레퍼런스는 절대 카운터와 baseline 의 차이로 감지를 본다
  (`guide_detected()`). 각 try 시작에서 baseline 을 갱신한다. 우리도 같게 — 카운터를
  0으로 리셋하지 않으므로 ISR 과의 경쟁이 없다.
- **준비 구간 감지는 cnt 에 넣지 않는다**(C009). 본 세척 진입(`RINSE_REQ_START`)에서
  baseline 을 다시 잡아 `cnt = guide_edge_count - baseline` 이 0부터 시작하게 한다.

### 5.3 회차 진행 — cnt 가 시간을 대체한다 (C014·C016·C018)

| cnt | 사건 | 상태 |
|---|---|---|
| 0 | 급수 종료, 회차시계 `t_cycle` 기산 | `RINSE_REQ_START` → `RINSE_WASH` |
| **20** | 급수 허가 상실(`hw_water_allowed`→0) → **배수문 열기** | `RINSE_WASH` → `RINSE_DRAIN_OPEN_C` |
| 20~40 | 배수하며 교반 계속 | `RINSE_DRAIN_OPEN_W` → `RINSE_DRAIN_STIR` |
| **40** | `hw_cycle_complete`→1 → **교반 정지 ≤50ms** + 도달시간 래치 | `RINSE_DRAIN_STIR` → `RINSE_CYCLE_CHECK` |

- **시간으로 완료하지 않는다**(C016). cnt 가 40에 못 미치면 아무리 오래 돌아도 완료가 아니다.
  → 상한이 없으면 T0 120분 안에 가열이 못 들어갈 수 있다는 것이 **N3**(회신 대기)의 요지다.
  N3 회신 전까지 `RINSE_CYCLE_MAX_MS` 를 `#ifndef` + `/* TBD: N3 */` 로 자리만 만든다.
- **열림 대기 중 cnt=40**(C020): `RINSE_DRAIN_OPEN_W` 에서도 cnt 를 보고, 40 도달 시 즉시
  교반을 멈춘다(문 구동은 계속). 레퍼런스 `ZG_R015` 가 `if (!in->hw_cycle_complete)` 로
  교반을 감싸는 것과 같다.
- **잔수배수 개념 소멸**(C018): `DJ_RINSE1_DRAIN_MS`(30s)·`DJ_RINSE2_DRAIN_MS`(90s)·
  `MOEUM_DRAIN_STIR_MS` 전부 폐기.

### 5.4 완료 판정 (C015·C021·C022)

`RINSE_CYCLE_CHECK` 에서 **세 조건이 모두** 성립해야 `done++`:

```c
t_cycle >= RINSE_MIN_CYCLE_MS   /* 60000, ZG_HW_MIN_CYCLE_MS — 과속 아님 (C015) */
&& !in.hw_stir_fault            /* 이상 이력 없음                              */
&& in.drain_open                /* 배수문 실제 열림                            */
```

- **회차시계 `t_cycle` 은 급수 종료 기산**(검토서 §4.3). `RINSE_REQ_START` 진입 tick.
- **`done` 중복 증가 금지**(C021): `completion_seen` 플래그로 같은 완료 신호를 한 번만
  소비한다. 레퍼런스 `ZG_R018` 의 `if (!c->completion_seen)` 와 동일. 플래그는 다음 회차
  진입(`RINSE_REQ_PREPARE`)에서 해제.
- **이상 이력은 반복으로 소거되지 않는다**(C022): `hw_stir_fault` 는 `rinse_lock` 이
  소유하고, **모드 이탈 + 새 준비 탐색**에서만 지워진다. 회차를 다시 돌린다고 지워지지 않는다.

### 5.5 이상 처리 — 교반만 차단한다 (C010·C062)

R2는 `DJ_ERROR`/`MOEUM_ERROR` 에서 `Jungji_StopAll()` 로 **전 부하 17종**을 정지시킨다.
R3 절대조건 ①은 이를 금지한다:

| | R2 | R3 (`RINSE_FAULT`) |
|---|---|---|
| 교반 | 정지 | **정지** (유일하게 차단되는 것) |
| 급수 | 정지 | 허가 유지 |
| 배수 | 정지 | 허가 유지 |
| 히터 | 정지 | 허가 유지 |
| 분쇄 | 정지 | 허가 유지 |

`RinseOutputs.stir_rpm` 을 0으로 고정하고 나머지 지령은 그대로 내보낸다. 호출부는
`Jungji_StopAll()` 을 **부르지 않는다**. → `jungji.c` 의 해제 절차 변경은 **C063**(N4 안전
이의 회신 대기)과 묶여 있으므로, 이 모듈에서는 "부르지 않는다"까지만 한다.

## 6. `rinse_lock` — UL1 상당 (MCU 구현)

```c
/* rinse_lock.h */
typedef enum { RINSE_GUIDE_OK=0, RINSE_GUIDE_MISSING, RINSE_GUIDE_OVERSPEED } RinseGuideFault;

void RinseLock_Init(void);
```

| 합성 신호 | 규칙 | 선행 |
|---|---|---|
| `hw_water_allowed` | `cnt < RINSE_WASH_EDGES(20)` | I02 |
| `hw_cycle_complete` | `cnt >= RINSE_TOTAL_EDGES(40)` | I02 |
| `hw_stir_fault` ← 가이드 미감지 | 준비 탐색 3회 실패 | — |
| `hw_stir_fault` ← **순이동**(C060/BG6) | `\|정−역 누적\| >= ceil(1.25 × 4P)` 인데 새 감지가 없으면 이상 | **I03 — P 미실측** |
| `hw_stir_fault` ← **과속**(C061/BG7) | 명목 40rpm 초과. R3는 UL2(LM2917), REV02는 없음 → 교반 BLDC FG + 엣지 간격으로 대체 | **I03** |

> **I03(감속비 P) 미실측이 C060·C061 을 막는다.** 값이 없으면 `RINSE_NET_TRAVEL_LIMIT` 를
> 박을 수 없다. CLAUDE.md §2 규칙대로 `#ifndef` + `/* TBD: I03 */` 로 자리만 만들고,
> **기본값은 "감시 비활성"(0 = 검사 안 함)** 으로 둔다 — 임의값으로 오검출을 만들지 않는다.

## 8. 교반 — 회전수 운전 엔진 (★v2 전면 개정)

> v1 의 "`dj_stir_alt_tick()` 을 `Rinse_StirTick()` 으로 공용화" 계획은 **폐기**됐다. 개정4 가 시간 패턴 자체를
> 없앴기 때문이다.

교반은 **벤더 `rotation.c`(0.3.0, 본문 무수정) + 우리 어댑터 `rotation_port`** 가 맡는다.

```
rotation.c (벤더, HW 무관)   zg_rotation_tick(profile, cfg, in) → 0 정지 / 1 CW / 2 CCW
        ▲ in                                             │ out
rotation_port.c (우리)  RotStir_Tick(r, permitted, now) ─┘
   position      ← BldcCtrl_Position(M2)  × "위에서 본 CW=+" (N14: M2 DIR_CW = 위에서 반시계)
   stir_at_rest  ← BldcCtrl_IsAtRest(M2)  (운전 사이 정지 = BldcCtrl_CoastAwake, §0.25)
   out 변화 시에만 → BldcCtrl_Start / CoastAwake,  실패 → BldcCtrl_Stop + E09
```

| 헹굼 구간 | 프로파일 | 운전 | 종료 (④ 현재) | 종료 (⑥ 이후) |
|---|---|---|---|---|
| R012~R013 본 세척 | `ZG_ROT_WASH` | CW×5 → CW/CCW/CW/CCW/CW = 10회(20회전) | 엔진 10회 완료 | **HW cnt 20 우선**(rinse_lock) |
| R014~R016 배수 | `ZG_ROT_DRAIN` | CW 만 최대 10회. **문 여는 중에도 돌고 센다** | 엔진 10회 완료 | **cnt 40 우선**, 이상 차단 우선 |

- **WASH→DRAIN 전환**은 `RotStir_Switch()` — 엔진이 스스로 정지 확인 + 2 s 대기 후 시작한다(돌던 모터를 뒤집지 않음).
- **HW 20/40 마일스톤을 합성하지 않는다**(벤더 계약 count_mismatch). HS6 증가분은 `RotStir_t.edges` 로 **관측만**.
- 건조·식힘(PROCESS, ⑤)은 아직 `dj_stir_alt_tick()` 시간 패턴 — ⑤ 에서 `ZG_ROT_PROCESS` 로 교체.
- `dj_stir313_tick()`(배출 전용) 유지.

| 종전 | ④ 이후 |
|---|---|
| `moeum_stir_tick()` + `MoeumStirPhase` 제어 | **삭제**. `MoeumStirPhase` 는 앱 보고용 **미러**로만 남음 |
| `dj_stir_rinse_tick()` | **삭제**. `dj_rot_tick()` → `RotStir_Tick()` |
| `MOEUM_STIR_CYCLES`·`MOEUM_DRAIN_STIR_MS`·`DJ_RINSE_STIR_MS`·`DJ_RINSE1/2_DRAIN_MS` | `#if ZG_TRACKED_ONLY`(기본 0 → 정의 없음) |
