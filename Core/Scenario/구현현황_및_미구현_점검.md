## 0. 한 줄 결론

**드라이버(HAL 추상화) 계층은 R1 넷리스트로 동기화 완료되어 거의 완성 상태이고, 시나리오 "제어·상태머신 계층"은 1·2단계(모음·동작)가 구현되었다.** 펌웨어는 부팅 → 드라이버 초기화 후, **마개 위치 홀센서(HS1~5)를 상시 디코딩하는 중재자**(`mode_arbiter`)가 고른 모드로 (A) 대기/테스트벤치 / (B) 모음 / (C) 동작 / (D) 강음·(E) 배수(스텁) / (F) 정지(★2026-08-25 신설 `APP_MODE_JUNGJI`, 표시 전용 — 실행은 대기와 동일) 상태머신을 **배타 실행**한다. 정지 동작 자체는 `jungji` 한 곳으로 단일화되어 있다. 나머지 공정(자가세척·살균세척)·단계 간 자동 전이·강음/배수 시퀀스 본체·음성 안내는 아직 미구현이다.

> ★2026-08-09 구현: [moeum.c/.h](moeum.c)(1단계 모음) · [dongjak.c/.h](dongjak.c)(2단계 동작, 원본 `doc/R1/zerogeo_scenario.docx`) — `Core/Scenario/`. `freertos.c`의 `StartDefaultTask`(센서 `*_SenseTick`)·`StartMotorTask`(모터 `*_MotorTick`)에 배치. **둘 다 벤치 확정 대기**(§4.2·§4.3).
> ★2026-08-15 구현: [mode_arbiter.c/.h](mode_arbiter.c)(동작트리거 중재자, `g_app_mode` 소유) · [jungji.c/.h](jungji.c)(정지 단일 처리) · [kangeum.c/.h](kangeum.c)·[baesu.c/.h](baesu.c)(HS1/HS4 연결부 스텁). 상세 §0.6.

> **R0 대비 R1의 하드웨어 변화(§3 상세)**: 도어 홀 리미트 신규(PF2~PF5), 리프트 GPIO→**TIM4 PWM** 승격, **DC 전류센싱 3채널** 신규, 조작부 홀 확장기 **U10 7ch → U24 8ch(0x3B)**. 이전판의 드라이버/핀 매핑 상당수는 이 변화로 폐기됨.

### 반영 완료 (코드 수정)
- **교반 패턴 정정 (기획서 4.2)**: 건조 교반을 docx의 `CW3/정지2 ×5 → CCW3`에서 **기획서 `CW3/정지2/CCW3 반복`(단순 3-phase)** 으로 정정. `dongjak.h DJ_STIR_FWD_REPS 5→1`. (RPM 20 유지)
- **4.5 추가 투입 금지 / 비상 정지 — 동작·모음 양쪽 구현**:
  - 처리 중 투입구 마개가 시작 위치(**동작=HS2 / 모음=HS5**)를 이탈하면(HS LOW 연속 `*_LID_CONFIRM_SAMPLES`=3회 ≈300ms 디바운스) 전 액추에이터 즉시 정지.
  - **동작**: 신규 상태 `DJ_ABORTED` — 고온(≥80℃)이면 냉각팬(BLDC+배기) 유지하며 안전 식힘, 식으면 전부 OFF 후 `DJ_IDLE` 복귀. **모음**: 히터 없어 즉시 안전정지 → `MOEUM_IDLE`.
  - **벤치 강제시작(`dbg_force_start`)은 lid 감시 무장 제외**(HS 없이 도는 벤치에서 즉시 오정지 방지). `*_LID_OPEN_ABORT` 매크로로 on/off.
  - **정지 요청 경로**: `Dongjak_RequestStop()`/`Moeum_RequestStop()` + `dbg_force_stop` 훅. 실제 정지원은 **마개 HS3 / 마개 이탈(HS_LOST) / 앱 W명령(`PROTO_ACT_STOP`) / 디버거(`g_jungji.dbg_stop_req`)** 4가지다. ★2026-08-18: **멤브레인 버튼 제어 폐지**(`ExtGpio/membrane.*` 삭제) — "정지버튼 3초 홀드"는 요구에서 제외됨.
- **급수 WATER_ON(PE2) 연동**(`DJ_FILL_USE_WATER_ON`): 헹굼 FILL 시 PB13+PE2 함께 ON(수위센서 통수 조건). 모음과 동일.
- **배수밸브 VALVE_DRAIN_CLN(PB14) 연동**(`DJ_DRAIN_VALVE_USE`): 배수문 개방=밸브 ON / 닫힘=OFF 불변식.
- **내부정화팬(FAN_EXHAUST) 시작시점 정정**: 기획서 7-② "홀센서 인식 즉시" → 시나리오 시작(`DJ_RINSE1_CLOSE` 진입)부터 10/5s 연속(기존 HEAT 진입 시작에서 앞당김).
- **도어 리밋홀 모니터 테스트벤치 `tb_doorhall` 신규**(WHALL/THALL PF3/PF4/PF2/PF5) + 벤치옵션 `DJ_DOOR_LIMIT_OPTIONAL`.
- **헹굼 세부단계 평탄화 + 2회 고정 언롤(moeum `MoeumState` 방식)**: 기존 `DJ_RINSE` 단일 상태 + 내부 `rinse_phase` 계층을 폐지하고 세부단계를 **최상위 `DongjakState`로 승격**. 나아가 **헹굼 2회를 고정 상수로 언롤**(카운터 `rinse_iter` 폐지) — 1차 `DJ_RINSE1_CLOSE/FILL/FILL_EXTRA/STIR/OPEN/DRAIN`(값 1~6), 2차 `DJ_RINSE2_*`(7~12). `g_dongjak.state` 하나로 회차+세부단계 모두 관찰. 진입동작은 `dj_enter()`, 스텝 로직은 `dj_rs_*` 헬퍼로 1·2차 공유, 타이밍은 `state_since` 기준. 병렬 서브FSM(교반+분쇄+수증기 동시)이 있는 `DJ_HEAT` 이후는 계층 유지.
- **헹굼 시간/배수 정정(사용자 지정)**: ① 교반 2분30초→**2분**(`DJ_RINSE_STIR_MS=120000`, 동작 전용). ② 배수는 **문 열린 채 교반하며 물빼기**(기존 수동 대기→능동 교반): 1차 **30초**(`DJ_RINSE1_DRAIN_MS`), 2차 **90초**(`DJ_RINSE2_DRAIN_MS`=물빼기30초+잔수60초). ③ 2차 배수가 잔수배수를 흡수 → **별도 `DJ_DRAIN_RESIDUAL`(2분) 상태 폐지**, 2차 배수 후 곧바로 `DJ_HEAT`. 상태값 총 20개(0 IDLE … 13 HEAT … 19 ABORTED).

## 0.6 2026-08-15 (2차 세션) — 동작트리거 중재자 도입 · 정지 단일화

> **문제 제기(사용자)**: "현재는 `g_app_mode` 변수를 런타임에서 바꿔야 동작하는 것 같다. 시나리오상 홀센서 HS1~5의 마개 위치에 따라 동작트리거가 되어야 한다."
> **점검 결론**: 맞다. 트리거가 **자기가 선택해야 할 모드 안에 갇혀 있었다.**

### 점검 결과 — 변경 전 구조의 결함 3가지
1. **순환 게이팅**: `Moeum_SenseTick()`/`Dongjak_SenseTick()`이 `g_app_mode`로 게이팅되어 있는데, 시작 홀(모음/동작) 에지를 **그 SenseTick 안에서만** 읽었다. 즉 *이미 그 모드에 들어가 있어야 그 모드의 시작 홀을 읽는다.* 기본값 `APP_MODE_TESTBENCH`에서는 마개를 아무리 돌려도 시작되지 않고, `g_app_mode`를 쓰는 코드는 선언부 외에 **전무**(= 디버거만 모드 변경 가능)했다.
2. **에지 기준선 stale**: `hs_prev`가 SenseTick 안에서만 갱신되는데 SenseTick 자체가 멈춰 있으므로 값이 얼어붙는다. → 부팅 시 마개가 이미 모음 위치면 **가짜 상승에지로 즉시 자동시작**, 반대로 stale HIGH면 **에지 누락으로 시작 불가**.
3. **전환 순서 버그**: `StartMotorTask`의 모드 변경 에지에서 `Moeum_Abort()`/`Dongjak_Abort()`를 부르는데, 이것이 방금 래치된 `start_req`를 지웠다.
4. (부수) **HS3 정지 / HS1 강음 / HS4 배수는 소비처가 전혀 없었다.** `abort_req`를 세우는 경로는 `dbg_force_stop`과 lid_guard(시작 홀 이탈) 둘뿐.

### 중재자 동작 규칙

### 정지 점검 — "즉시 vs 서서히"
- **BLDC 2대만이 유일하게 "서서히" 멎고 있었다.** `BldcCtrl_Stop()` → `DRV8306_Stop()`은 duty 0 + ENABLE LOW(sleep) = **코스트**라 관성 큰 분쇄날이 수 초간 계속 돈다. 마개 개방(= 손 접근 가능)에 대해 부족.
  → **`BldcCtrl_BrakeStop()`/`BrakeRelease()` 신규**([bldc_ctrl.c](../Devices/Motor/bldc_ctrl.c)): nBRAKE LOW 단락제동. **게이트 드라이버가 깨어 있어야만 유효**하므로 ENABLE HIGH 유지 → `JUNGJI_BRAKE_MS`(500ms) 뒤 `Jungji_Tick()`이 해제 + sleep.
- 나머지는 전부 즉시: 도어/리프트 = **웜기어 자기유지**(VM만 내리면 그 자리), 스텝모터 = 무여자, 밸브/팬 = GPIO.
- **히터는 출력만 즉시 끊기고 잔열이 남는다** → 80℃(`JUNGJI_COOL_TEMP_D10`) 이상이면 냉각팬(PG1/PG2)을 끄지 않고 **jungji가 직접** 온도 보며 유지. 시나리오(DJ_ABORTED)에 맡기면 모드 전환 시 리셋되며 냉각이 끊기기 때문. 써미스터 오류값은 "모름" → 안전측(고온 취급).

### 구현 중 발견·차단한 함정 3건
1. `Jungji_Scenarios()`의 `Moeum_Abort()`/`Dongjak_Abort()`가 내부에서 `BldcCtrl_Stop()`(=sleep)을 불러 **방금 건 단락제동을 무효화**한다. → `Jungji_StopAll()`에서 Scenarios를 **맨 먼저**, `Jungji_Bldc()`를 **맨 마지막**에 배치 + 제동 중이면 무조건 재확립(멱등).
2. `Jungji_Testbench()`가 `tb_fan_exhaust_en`까지 0으로 내리는데 TESTBENCH 모드에선 `TB_GpioOut_Poll()`이 매 틱 플래그를 핀에 미러링 → **켜 둔 냉각팬을 곧바로 다시 끈다.** → `Jungji_Fans()`가 핀과 tb 플래그를 **함께** 쓴다.
3. `TB_TCA9554_Poll()`(키패드)이 `BldcCtrl_Start()`를 부르면 nBRAKE를 풀어 버린다 → **제동 홀드 중엔 키패드 폴링을 건너뛴다**(`freertos.c`).

## 4. 시나리오 단계별 미구현 항목 (R1 기준 갱신)

> 공통: 1·2단계(모음·동작)는 독립 상태머신으로 구현됨(§4.2·§4.3). **전 단계를 묶는 통합 메인 상태머신·시퀀서는 아직 없음.** 아래는 각 단계 실현에 추가로 필요한 로직.

### 4.1 공정 전체 (프레임워크)
- ⚠️ **메인 상태머신**: 대기 → 모음 → 동작 → 자가세척 → 살균세척 → 리셋 (+배수/정지/찰음·강음). ★2026-08-15부로 **마개 위치(HS1~5)에 의한 모드 선택·전환·정지는 `mode_arbiter`가 담당**(§0.6). 남은 공백은 **단계 간 자동 연결**(모음 완료 → 동작 자동 전이, 처리횟수 기반 자가/살균 자동 진입) — 이는 마개 조작이 아니라 시나리오 완료 이벤트로 넘어가는 부분이라 별건.
- ⚠️ **시퀀스 타이밍 엔진**: 모음/동작 내부에 서브-FSM 타이머로 구현됨(CW/정지/CCW, 분/초 마커). 단, 재사용 가능한 공용 엔진으로 추출되진 않음(각 시나리오가 자체 보유).
- ✅ **명령 입력 디코드 — 구현됨(★2026-08-15)**: `mode_arbiter.c`가 U24 HS1~5(마개 위치)를 모드와 무관하게 상시 디코딩 → 강음/모음/정지/배수/동작 명령으로 변환. 정확히 1비트만 유효 + 3샘플 디바운스 + 전이 에지 판정. 정지 계열(HS3·전채널 미인식·다중 인식)은 `jungji`로 위임.
- ⚠️ **처리 횟수 카운터**: 동작 완료 시 `g_dongjak.cycle_count` 증가 구현. 단 5회 후 자가세척 / 6회 후 살균 **자동 진입 연결은 미구현**.
- ❌ **알림/음성 상태 안내** 프레임워크(현재 비프만).

### 4.2 1단계 — 모음(헹굼) ★구현됨 (벤치 확정 대기)
> 구현: [moeum.c/.h](moeum.c). HW 매핑은 [사용자_시나리오 §4.1.1](사용자_시나리오_검토정리.md) 참조.
- ✅ 드라이버 준비: 배수문(U5)·급수밸브(VALVE_DRY_IN)·교반(M2)·도어 홀 리미트·수위 EXTI **모두 존재**.
- ✅ **상태머신 구현**: `MOEUM_IDLE→DOOR_CLOSE→FILL→FILL_EXTRA→STIR→DRAIN_OPEN→DRAIN_WAIT→DONE`(+`ERROR`). `Moeum_MotorTick`(1ms) 소유, `Moeum_SenseTick`(100ms) 센서.
- ✅ **수위센서(PF6/PF7) → 급수 정지**: 감지 후 2초 추가급수(`MOEUM_FILL_EXTRA_MS`) 후 VALVE_DRY_IN(PB13) OFF. *(감지 기본=EXTI 에지, 레벨 폴백은 `MOEUM_WATER_USE_LEVEL` opt-in)*
- ✅ **교반 30RPM CW6초/정지1초/CCW6초 × 11 = 143초(2분23초)**: 교반 서브-FSM + `BldcCtrl_Start/Stop`(M2) + `target_out_rpm=30`. *(2026-08-26: 1cycle 13초. 목표 총시간 2분30초(150초)에 **사이클을 내려서** 맞춘 값 — `floor(150/13)=11`. 이력: 25RPM 3/1/3×22=154초 → 30RPM 4/1/4×22=198초 → 현재.)* 상세 §0.8
- ✅ 배수문 닫힘(W-HALL-CLOSE PF3)/열림(W-HALL-OPEN PF4) 인식 → 모터 정지, 열림 후 **30초 뒤 교반 정지**(`MOEUM_DRAIN_STIR_MS`, ★2026-08-26 1분→30초). 앱은 이 값을 `enums.MOEUM_DRAIN_WAIT_MS`로 복제하므로 **함께 고칠 것**.
- ✅ 안전 타임아웃(급수 미도달 → `MOEUM_ERROR` 안전정지). ⚠️**도어는 2026-08-25부로 타임아웃 ERROR 없음** — 시간 상한(닫힘 4.2초/열림 6초)이 정상 종료다.
- ✅ **4.5 비상정지(투입구 개방)**: ★2026-08-15부로 **중재자+jungji가 담당**(§0.6). 마개가 모음 위치를 벗어나 어느 홀도 인식되지 않으면(3샘플) `JUNGJI_SRC_HS_LOST` 비상정지 → 전 액추에이터 정지(교반 BLDC는 **단락제동**) → IDLE. ## 6. 모음 docx(§4.1.1) ↔ R1 코드 정합 체크

`제로지오_모음기능_펌웨어제어.docx` 매핑을 코드와 대조: **핀·넷·EN경로 대부분 일치**(PC6/PC7, W-HALL PF3/PF4, VALVE-DRY-IN PB13, WATER-SEN PF6/PF7, M2 교반 PE8/PE11/PE12/PE14, U24 0x3B/INT PF9).

⚠️ **문서 오기 1건**(사용자_시나리오 §4.1.1에 정정 주석 반영):
- docx: 배수문 = **U11 DRV8871 / TIM8_CH1/2**
- R1 코드: 배수문 = **U5 / TIM3_CH1/2**(`wdoor.h`), 그리고 **U11 = 분쇄 BLDC(drv8306 M1)**(`drv8306.h` "netlist U11 = M1")
- → docx의 U11·TIM8은 오기. 물리 배선(PC6/PC7)은 정상. 지정번호/타이머는 **코드 기준(U5/TIM3)** 채택.

## 8. 요약

- **완성**: 전 드라이버(BLDC 폐루프·도어+홀리미트·리프트PWM·스테퍼·팬·밸브·센서·DC전류·통신·키패드·비프) — R1 동기화 완료, 개별 구동 가능.
- **시나리오 구현(2개)**:
  - **1단계 모음**([moeum.c](moeum.c)) — 닫힘→급수→수위+2초→교반 11사이클(143초)→배수개방→30초 후 정지.
  - **2단계 동작**([dongjak.c](dongjak.c), 원본 `doc/R1/zerogeo_scenario.docx`) — 헹굼2회→잔수배수→건조(히터 히스테리시스+교반+분쇄 프로파일+수증기+팬 동시)→110분 2000역회전→120분 식힘→수거통확인→130분 배출→배수부 개방.
- **입력/모드 계층 ★2026-08-15 신규**: [mode_arbiter.c](mode_arbiter.c)가 **마개 위치 홀(HS1~5)을 모드와 무관하게 상시 디코딩**해 모드를 결정한다 — 이전에는 트리거가 자기가 선택해야 할 모드 안에 갇혀 디버거로만 전환이 가능했다(§0.6). 정지는 [jungji.c](jungji.c)로 단일화(부하 17종, BLDC 단락제동, 잔열 냉각 인계). 강음/배수는 **연결부만** 있는 스텁([kangeum.c](kangeum.c)/[baesu.c](baesu.c)).
- **공백**: **3·4단계(자가세척·살균세척)**, 단계 간 자동 전이(모음↔동작↔자가/살균), 강음·배수 시퀀스 본체, DC모터 부하 해소, 음성 안내, 사용자/원격 UI.
- **확정 선행**: [하드웨어결정_잔여항목.md](하드웨어결정_잔여항목.md) §1~3 (DC전류·OSC리맵·극성·써미스터 채널·스테퍼 역할·팬 역할) + 신규 2건(`MODEARB_CONFIRM_SAMPLES`·`JUNGJI_BRAKE_MS`). *U24 홀 의미는 확정됨.* 안전 락(80/60℃·210℃·배출 2분 타이머)은 **HW 처리**이며 FW는 감시/구동만.
- 즉, **"부품은 R1로 다 움직이고, 1·2단계 레시피 + 마개로 고르는 입력 계층까지 나왔다 — 벤치 검증 후 3·4단계·단계 자동전이로 확장"** 이 현 상태다.
