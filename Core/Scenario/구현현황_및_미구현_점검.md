## 0. 한 줄 결론

**드라이버(HAL 추상화) 계층은 R1 넷리스트로 동기화 완료되어 거의 완성 상태이고, 시나리오 "제어·상태머신 계층"은 1·2단계(모음·동작)가 구현되었다.** 펌웨어는 부팅 → 드라이버 초기화 후 런타임 모드(`g_app_mode`)로 (A) 테스트벤치(디버거/키패드 개별 모터) / (B) 모음 / (C) 동작 시나리오 상태머신을 **배타 실행**한다. 나머지 공정(자가세척·살균세척·배수·찰음)·통합 모드 전환·음성 안내는 아직 미구현이다.

> ★2026-08-09 구현: [moeum.c/.h](moeum.c)(1단계 모음) · [dongjak.c/.h](dongjak.c)(2단계 동작, 원본 `doc/R1/zerogeo_scenario.docx`) — `Core/Scenario/`. `freertos.c`의 `StartDefaultTask`(센서 `*_SenseTick`)·`StartMotorTask`(모터 `*_MotorTick`)에 배치, 테스트벤치와 런타임 배타 선택(`g_app_mode`: TESTBENCH/MOEUM/DONGJAK). **둘 다 벤치 확정 대기**(§4.2·§4.3).

> **R0 대비 R1의 하드웨어 변화(§3 상세)**: 도어 홀 리미트 신규(PF2~PF5), 리프트 GPIO→**TIM4 PWM** 승격, **DC 전류센싱 3채널** 신규, 조작부 홀 확장기 **U10 7ch → U24 8ch(0x3B)**. 이전판의 드라이버/핀 매핑 상당수는 이 변화로 폐기됨.

## 1. 현재 코드 아키텍처 (R1)

```
main.c
  └ MX_*_Init: GPIO/ADC1/DAC/I2C1/SPI1/TIM1(BLDC)/UART4·5/TIM7/TIM3(도어)/TIM4(리프트)
  └ USER CODE: __HAL_AFIO_REMAP_PD01_ENABLE()(도어EN용) · Lift_Init · WiFi_Init · BLE_Init
              · (Membrane_Init 비활성 — tb_tca9554가 U8/U9 점유) · LM4871_BoardInit
  └ FreeRTOS 시작 (i2c1_mutex 생성)

freertos.c — 태스크 2개 + 런타임 모드(g_app_mode: TESTBENCH 기본 / MOEUM / DONGJAK)
  ├ StartDefaultTask (100ms 주기)
  │    · AdcCtrl_Init → Distance / Thermistor×3 / (DC전류 3ch 접근 가능) 폴링
  │      └ enable 게이팅 모니터: tb_distance(Distance-SEN, 동작확인✓) · tb_thermistor
  │    · HallSensor(U24 HS1~8) INT 서비스 + 주기 폴링 → g_hall_mask 갱신
  │    · Membrane_Poll() 비활성(테스트벤치가 U8/U9 점유)
  │    · [MOEUM]   Moeum_SenseTick()   — HS2 시작감지·수위감지(센서만)
  │    · [DONGJAK] Dongjak_SenseTick() — HS5 시작·온도·수위·수거통 fill%(센서만)
  └ StartMotorTask (1ms 주기)  — 모드로 배타 실행, 전환 순간 전 모터 정지
       · [TESTBENCH] MotorTask_RunTestbench(): TB_DRV8871(도어 U5/U7)·TB_StepMotor
       ·   ·TB_TCA9554_Poll(키패드 U9)→BLDC 지령·BldcCtrl_Tick(M1/M2)·TB_Lift_Poll
       · [MOEUM]     MotorTask_RunMoeum(): Moeum_MotorTick() + BldcCtrl_Tick(M2)
       · [DONGJAK]   MotorTask_RunDongjak(): Dongjak_MotorTick()(히터·교반·분쇄·
       ·             도어·스테퍼·팬) + BldcCtrl_Tick(M1 분쇄, M2 교반)
```

- **계층 구성**: `Interface/`(gpio_ctrl·adc_ctrl 명명형 접근) → `Devices/`(장치별 드라이버) → `Testbench/`(디버거·키패드 수동 구동). **그 위의 "애플리케이션/시나리오" 계층은 비어 있음.**
- 드라이버는 완성도 높음. 미검증/미확정은 대부분 (a) 방향·극성 부호(벤치 확인), (b) DC전류 캘리브레이션·임계, (c) HS 채널↔기구 의미 매핑 → [하드웨어결정_잔여항목.md](하드웨어결정_잔여항목.md).

## 3. R0(이전판) 대비 R1 변경점 — 이전 문서 폐기 근거

| 이전판(R0, 2026-07-28) 주장 | R1 실제 |
|---|---|
| "리미트 스위치 **없음**, 문은 모터 동작시간(타이머)으로 위치제어" | ❌ **도어 홀 리미트 신규**: W-HALL PF3/PF4, T-HALL PF2/PF5. `[TW]Door_AtOpen/AtClose()` 제공 |
| 바이메탈 `BIMETAL1~5 = PF0~PF4` EXTI 5채널 | ❌ **PF2~PF5 = 도어 홀센서로 재배정**. 바이메탈 EXTI 제거(HW 차단 경로로만 추정) |
| 바이메탈 게이팅 임계 **50/80/200℃** | ❌ 시나리오 개정 **60/80/210℃**(사용자_시나리오 §0·§3.1) |

| 모터 과부하 감지 "핸들 없음"(§5.2) | ✅ **`dc_current.c` 3채널 신규**(임계·매핑 미정) |

## 4. 시나리오 단계별 미구현 항목 (R1 기준 갱신)

> 공통: 1·2단계(모음·동작)는 독립 상태머신으로 구현됨(§4.2·§4.3). **전 단계를 묶는 통합 메인 상태머신·시퀀서는 아직 없음.** 아래는 각 단계 실현에 추가로 필요한 로직.

### 4.1 공정 전체 (프레임워크)
- ⚠️ **메인 상태머신**: 대기 → 모음 → 동작 → 자가세척 → 살균세척 → 리셋 (+배수/정지/찰음·강음). 현재는 모음·동작을 `g_app_mode`로 **배타 선택** 실행 — **단계 간 자동 연결·모드 전환은 미구현**(예: 모음↔동작 자동 전이, 처리횟수 기반 자가/살균 진입).
- ⚠️ **시퀀스 타이밍 엔진**: 모음/동작 내부에 서브-FSM 타이머로 구현됨(CW/정지/CCW, 분/초 마커). 단, 재사용 가능한 공용 엔진으로 추출되진 않음(각 시나리오가 자체 보유).
- ❌ **명령 입력 디코드**: U24 HS 채널(마개/조작부 위치) → 명령 변환. 현재 `g_hall_mask` 원시 비트만(모음=HS2·동작=HS5 인덱스 가정).
- ⚠️ **처리 횟수 카운터**: 동작 완료 시 `g_dongjak.cycle_count` 증가 구현. 단 5회 후 자가세척 / 6회 후 살균 **자동 진입 연결은 미구현**.
- ❌ **알림/음성 상태 안내** 프레임워크(현재 비프만).

### 4.2 1단계 — 모음(헹굼) ★구현됨 (벤치 확정 대기)
> 구현: [moeum.c/.h](moeum.c). HW 매핑은 [사용자_시나리오 §4.1.1](사용자_시나리오_검토정리.md) 참조.
- ✅ 드라이버 준비: 배수문(U5)·급수밸브(VALVE_DRY_IN)·교반(M2)·도어 홀 리미트·수위 EXTI **모두 존재**.
- ✅ **상태머신 구현**: `MOEUM_IDLE→DOOR_CLOSE→FILL→FILL_EXTRA→STIR→DRAIN_OPEN→DRAIN_WAIT→DONE`(+`ERROR`). `Moeum_MotorTick`(1ms) 소유, `Moeum_SenseTick`(100ms) 센서.
- ✅ **수위센서(PF6/PF7) → 급수 정지**: 감지 후 2초 추가급수(`MOEUM_FILL_EXTRA_MS`) 후 VALVE_DRY_IN(PB13) OFF. *(감지 기본=EXTI 에지, 레벨 폴백은 `MOEUM_WATER_USE_LEVEL` opt-in)*
- ✅ **교반 25RPM CCW3초/정지1초/CW3초 × 22 = 2분30초**: 교반 서브-FSM + `BldcCtrl_Start/Stop`(M2) + `target_out_rpm=25`.
- ✅ 배수문 닫힘(W-HALL-CLOSE PF3)/열림(W-HALL-OPEN PF4) 인식 → 모터 정지, 열림 후 **1분 뒤 교반 정지**(`MOEUM_DRAIN_STIR_MS`).
- ✅ 안전 타임아웃(도어·급수 미도달 → `MOEUM_ERROR` 안전정지) — 스펙 외 placeholder.
- 🔲 **벤치 확정 필요**: HS2 시작채널(`MOEUM_HS_START_IDX`, §5-2)·수위 극성/에지(§5-1)·도어 리미트 극성(하드웨어결정 §2-1)·교반/도어 RPM·듀티·타임아웃 값.
- 🔲 완료조건 "21분 30초"(총시간/반복 정의) 미확정 — 현재 구현은 **헹굼 1사이클** 흐름(§9-1). 총시간 정의 확정 시 반복 래퍼 추가 필요.

### 4.3 2단계 — 동작(건조·분쇄·배출) ★구현됨 (벤치 확정 대기)
> 구현: [dongjak.c/.h](dongjak.c). **★기준 원본: `doc/R1/zerogeo_scenario.docx`([2단계] 동작, 2026-07-30)** — 사용자_시나리오_검토정리.md와 타이밍이 다르며 docx가 최신·우선.
> 시간 마커는 **홀 감지(시나리오 시작) 절대시간** 기준(110/120/130/135분).
- ✅ **상태머신 구현**: `DJ_IDLE→RINSE(2회)→DRAIN_RESIDUAL→HEAT→COOLDOWN→BIN_CHECK→DISCHARGE→DONE`(+`ERROR`). `Dongjak_MotorTick`(1ms) 소유 + `Dongjak_SenseTick`(100ms) 센서. 건조 구간은 히터/교반/분쇄/수증기/팬 **동시 제어**.
- ✅ **초기 헹굼 2회 + 잔수 배수**: 닫힘→급수→2초→교반 2분30초 ×2 → 배수문 열고 **2분 교반 배수**(DRAIN_RESIDUAL). *(헹굼 간 짧은 배수 추가 — docx "2~6번(배수제외)"은 에지 감지 교착/오버플로 위험이라 설계 판단으로 보완)*
- ✅ **히터 히스테리시스**: 195℃↑ OFF / 190℃↓ ON (+210℃ SW 보조; 주체는 HW 바이메탈). 써미스터 에러 시 유지.
- ✅ **분쇄 BLDC 프로파일**: 80℃↑ 게이팅 → 1500 CW 3·2초 3분(1차) → 1000 CW 연속 → **110분↑ 2000 CCW 4·2초**. 식힘 구간 1000 CCW→80℃서 OFF.
- ✅ **교반 BLDC**: 건조 = CW3/정지2 ×5→CCW3 @20RPM / 식힘·배출 = CW3/정지1/CCW3.
- ✅ **수증기 루프**: 100℃ 개방(방수팬→냄새관로 STEP1→흡입 STEP2), 84℃ 역순 폐쇄. `dj_vapor_tick` 스테퍼 페이싱(500PPS).
- ✅ **팬**: 내부정화팬(FAN_EXHAUST) 10·5초 유지(배출까지), BLDC식힘팬(BLDC_FAN) 80℃↑ 30·10초.
- ✅ **식힘(120분)·배출(130분)**: 히터 OFF·교반 유지 → 수거통 확인 → 배출문 2분 개방(개방 후 DC 미구동)+교반 배출 → 닫음 → **배수부 완전 개방**.
- ✅ **배출 전 수거통 확인**: 처리횟수(`cycle_count`)+분말높이(fill%) 판정, 미충족 시 대기(음성 안내 TODO).
- 🔲 **벤치 확정 필요**: 시작 HS 채널(`DJ_HS_START_IDX`=HS5 가정)·온도 써미스터 채널(`DJ_TEMP_CH`)·수위 극성/에지·도어 극성·스테퍼 역할/스텝수(`DJ_DUCT_STEPS`)·수거통 유무 홀·RPM/듀티/타임아웃 값.
- 🔲 **HW 처리 영역(FW 감시/구동만)**: 배수문/급수/분쇄 게이팅 래치(80℃·60℃ 바이메탈), 210℃ 차단, 배출문 2분 타이머·래치 리셋 — docx 4.2·4.3·6.1·9.1·10.1·11.
- 🔲 음성 안내(비움/배출완료)는 스피커 비프만 가능 → 멘트 미구현.

### 4.4 3단계 — 자가세척
- ❌ "음식물 없는 상태에서 1단계 헹굼 1회" 재사용 호출(상태머신 분기). **5번째 처리 후 자동**.

### 4.5 4단계 — 살균세척
- ❌ **6회 처리 후 → 소비자 "세척 버튼" 선택 시** 진입(자동 아님). 안내 5초×3회.
- ❌ 급수→가열→교반/분쇄 반대회전→**100℃ 5분 유지**→**배수구 30초 배수**→리셋 전체 시퀀스. (이전판 "수거통 배출·10분 끓임"은 폐기)

### 4.6 배수 / 4.7 찰음·강한음식
- ❌ 배수 보조: 15RPM 정5초/정지5초·역5초/정지5초 약 3분(뚜껑 닫으면 중지).
- ❌ 찰음/강음 보정 프로그램(1차 기본 후 업그레이드 예정, 파라미터 미확정).

### 4.8 모터 부하 해소 (§5.2) — ★R1 하드웨어 착수 가능
- ⚠️ DC 전류센싱 3채널 드라이버(`dc_current`) 존재. **임계·채널매핑 확정 후** "과부하→반대회전 최소 4회→정지·에러멘트" 로직 구현 가능.

### 4.9 테스트/AS 모드
- ❌ 멤브레인 "모터선택" 기반 정식 UI(3초 진입→모터선택→정/역 확인). 현재는 개발자용 테스트벤치.
- ❌ 설정값 EEPROM 저장(SPI1 핸들만 존재).

  - `g_app_mode`(TESTBENCH/MOEUM/DONGJAK)로 테스트벤치와 배타 실행. **둘 다 벤치 확정 대기**.
- **공백**: **3·4단계(자가세척·살균세척)**, 통합 메인 상태머신(단계 자동 전이), 명령 디코드, DC모터 부하 해소, 음성 안내, 배수/찰음 모드, 사용자/원격 UI.
- **확정 선행**: [하드웨어결정_잔여항목.md](하드웨어결정_잔여항목.md) §1~3 (DC전류·U24홀 의미/모음 HS2·동작 HS5·OSC리맵·극성·써미스터 채널·스테퍼 역할·팬 역할). 안전 락(80/60℃·210℃·배출 2분 타이머)은 **HW 처리**이며 FW는 감시/구동만.
- 즉, **"부품은 R1로 다 움직이고, 1·2단계 레시피가 나왔다 — 벤치 검증 후 3·4단계·통합으로 확장"** 이 현 상태다.
