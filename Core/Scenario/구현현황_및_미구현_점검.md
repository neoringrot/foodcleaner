## 0. 한 줄 결론

**드라이버(HAL 추상화) 계층은 R1 넷리스트로 동기화 완료되어 거의 완성 상태이고, 시나리오 "제어·상태머신 계층"은 1·2단계(모음·동작)가 구현되었다.** 펌웨어는 부팅 → 드라이버 초기화 후, **마개 위치 홀센서(HS1~5)를 상시 디코딩하는 중재자**(`mode_arbiter`)가 고른 모드로 (A) 대기/테스트벤치 / (B) 모음 / (C) 동작 / (D) 강음·(E) 배수(스텁) 상태머신을 **배타 실행**한다. 정지는 `jungji` 한 곳으로 단일화되어 있다. 나머지 공정(자가세척·살균세척)·단계 간 자동 전이·강음/배수 시퀀스 본체·음성 안내는 아직 미구현이다.

> ★2026-08-09 구현: [moeum.c/.h](moeum.c)(1단계 모음) · [dongjak.c/.h](dongjak.c)(2단계 동작, 원본 `doc/R1/zerogeo_scenario.docx`) — `Core/Scenario/`. `freertos.c`의 `StartDefaultTask`(센서 `*_SenseTick`)·`StartMotorTask`(모터 `*_MotorTick`)에 배치. **둘 다 벤치 확정 대기**(§4.2·§4.3).
> ★2026-08-15 구현: [mode_arbiter.c/.h](mode_arbiter.c)(동작트리거 중재자, `g_app_mode` 소유) · [jungji.c/.h](jungji.c)(정지 단일 처리) · [kangeum.c/.h](kangeum.c)·[baesu.c/.h](baesu.c)(HS1/HS4 연결부 스텁). 상세 §0.6.

> **R0 대비 R1의 하드웨어 변화(§3 상세)**: 도어 홀 리미트 신규(PF2~PF5), 리프트 GPIO→**TIM4 PWM** 승격, **DC 전류센싱 3채널** 신규, 조작부 홀 확장기 **U10 7ch → U24 8ch(0x3B)**. 이전판의 드라이버/핀 매핑 상당수는 이 변화로 폐기됨.

## 0.6 2026-08-15 (2차 세션) — 동작트리거 중재자 도입 · 정지 단일화

> **문제 제기(사용자)**: "현재는 `g_app_mode` 변수를 런타임에서 바꿔야 동작하는 것 같다. 시나리오상 홀센서 HS1~5의 마개 위치에 따라 동작트리거가 되어야 한다."
> **점검 결론**: 맞다. 트리거가 **자기가 선택해야 할 모드 안에 갇혀 있었다.**

### 점검 결과 — 변경 전 구조의 결함 3가지
1. **순환 게이팅**: `Moeum_SenseTick()`/`Dongjak_SenseTick()`이 `g_app_mode`로 게이팅되어 있는데, 시작 홀(HS2/HS5) 에지를 **그 SenseTick 안에서만** 읽었다. 즉 *이미 그 모드에 들어가 있어야 그 모드의 시작 홀을 읽는다.* 기본값 `APP_MODE_TESTBENCH`에서는 마개를 아무리 돌려도 시작되지 않고, `g_app_mode`를 쓰는 코드는 선언부 외에 **전무**(= 디버거만 모드 변경 가능)했다.
2. **에지 기준선 stale**: `hs_prev`가 SenseTick 안에서만 갱신되는데 SenseTick 자체가 멈춰 있으므로 값이 얼어붙는다. → 부팅 시 마개가 이미 모음 위치면 **가짜 상승에지로 즉시 자동시작**, 반대로 stale HIGH면 **에지 누락으로 시작 불가**.
3. **전환 순서 버그**: `StartMotorTask`의 모드 변경 에지에서 `Moeum_Abort()`/`Dongjak_Abort()`를 부르는데, 이것이 방금 래치된 `start_req`를 지웠다.
4. (부수) **HS3 정지 / HS1 강음 / HS4 배수는 소비처가 전혀 없었다.** `abort_req`를 세우는 경로는 `dbg_force_stop`과 lid_guard(시작 홀 이탈) 둘뿐.

### 중재자 동작 규칙
- 디코딩: `HallSensor_GetMask() & 0x1F`, **정확히 1비트만 유효**. `MODEARB_CONFIRM_SAMPLES=3`(≈300ms) 연속 동일해야 확정. 확정 위치가 **바뀐 에지**에서만 액션.
- HS1/HS2/HS4/HS5 → 모드 전환 + 해당 `*_Start()`. **HS3 → 비상정지 + 대기(TESTBENCH)**. **전 채널 미인식(마개 열림/이탈) → 비상정지, 모드는 유지**(마개 없는 벤치에서 디버거 조작 유지). 2채널 이상 동시 → 홀 이상으로 보고 정지만.
- **순서 고정**: 모드 전환은 항상 **정지 → 전환 → 시작**. 판단은 100ms SenseTick, 실행은 1ms MotorTick(`ModeArbiter_MotorTick`) — 위 결함 3을 구조적으로 제거.
- **부팅 후 첫 확정은 기준선만** 잡고 기동하지 않음(전원 인가 시 마개가 이미 모음/동작 위치여도 자동 시작 금지) — 결함 2를 제거.
- 시나리오 내부 HS 에지 검출은 `MOEUM_HS_TRIGGER_INTERNAL`/`DJ_HS_TRIGGER_INTERNAL` **= 0**(기본 OFF)로 전환. **`dbg_force_start`는 그대로 유효**(요구사항 유지).

### 정지 점검 — "즉시 vs 서서히"
- **BLDC 2대만이 유일하게 "서서히" 멎고 있었다.** `BldcCtrl_Stop()` → `DRV8306_Stop()`은 duty 0 + ENABLE LOW(sleep) = **코스트**라 관성 큰 분쇄날이 수 초간 계속 돈다. 마개 개방(= 손 접근 가능)에 대해 부족.
  → **`BldcCtrl_BrakeStop()`/`BrakeRelease()` 신규**([bldc_ctrl.c](../Devices/Motor/bldc_ctrl.c)): nBRAKE LOW 단락제동. **게이트 드라이버가 깨어 있어야만 유효**하므로 ENABLE HIGH 유지 → `JUNGJI_BRAKE_MS`(500ms) 뒤 `Jungji_Tick()`이 해제 + sleep.
- 나머지는 전부 즉시: 도어/리프트 = **웜기어 자기유지**(VM만 내리면 그 자리), 스텝모터 = 무여자, 밸브/팬 = GPIO.
- **히터는 출력만 즉시 끊기고 잔열이 남는다** → 80℃(`JUNGJI_COOL_TEMP_D10`) 이상이면 냉각팬(PG1/PG2)을 끄지 않고 **jungji가 직접** 온도 보며 유지. 시나리오(DJ_ABORTED)에 맡기면 모드 전환 시 리셋되며 냉각이 끊기기 때문. 써미스터 오류값은 "모름" → 안전측(고온 취급).

### 구현 중 발견·차단한 함정 3건
1. `Jungji_Scenarios()`의 `Moeum_Abort()`/`Dongjak_Abort()`가 내부에서 `BldcCtrl_Stop()`(=sleep)을 불러 **방금 건 단락제동을 무효화**한다. → `Jungji_StopAll()`에서 Scenarios를 **맨 먼저**, `Jungji_Bldc()`를 **맨 마지막**에 배치 + 제동 중이면 무조건 재확립(멱등).
2. `Jungji_Testbench()`가 `tb_fan_exhaust_en`까지 0으로 내리는데 TESTBENCH 모드에선 `TB_GpioOut_Poll()`이 매 틱 플래그를 핀에 미러링 → **켜 둔 냉각팬을 곧바로 다시 끈다.** → `Jungji_Fans()`가 핀과 tb 플래그를 **함께** 쓴다.
3. `TB_TCA9554_Poll()`(키패드)이 `BldcCtrl_Start()`를 부르면 nBRAKE를 풀어 버린다 → **제동 홀드 중엔 키패드 폴링을 건너뛴다**(`freertos.c`).

### 검증 상태
- ✅ 전체 Core 52개 소스 `-Wall` **경고 0**, 링크 성공(text 66,928 / bss 15,856). **HW 미검증**.
- 🔲 **벤치 확정 필요 2건**:
  - `MODEARB_CONFIRM_SAMPLES=3`(300ms) — 마개를 **천천히** 모음→동작으로 돌리면 중간의 HS3(정지)·HS4(배수)가 확정되어 트리거된다. 통과 위치를 무시하려면 값을 키우거나 "직전이 NONE일 때만 전환" 규칙 추가 필요. 실제 마개 조작감을 봐야 결정 가능.
  - `JUNGJI_BRAKE_MS=500` — 분쇄날 관성 실측 필요. 짧으면 서기 전에 코스트로 넘어가고, 길면 권선/FET 발열 증가.

| 조작부 홀 `U10 7채널(HS1~7)`, "9채널 필요·2채널 부족" | ⚠️ **U24 8채널(HS1~8) @0x3B**로 확장. 채널 수 여유↑, 단 채널↔기구 의미 여전히 미정 |

> **애플리케이션 계층**: 1단계 모음이 첫 상태머신으로 구현됨(§4.2). 나머지(동작·자가세척·살균세척)·통합 메인 상태머신·명령 디코드·히터 온도제어·배출 안전판정·음성안내·처리횟수/모드관리는 여전히 공백(§4).

## 4. 시나리오 단계별 미구현 항목 (R1 기준 갱신)

> 공통: 1·2단계(모음·동작)는 독립 상태머신으로 구현됨(§4.2·§4.3). **전 단계를 묶는 통합 메인 상태머신·시퀀서는 아직 없음.** 아래는 각 단계 실현에 추가로 필요한 로직.

### 4.1 공정 전체 (프레임워크)
- ⚠️ **메인 상태머신**: 대기 → 모음 → 동작 → 자가세척 → 살균세척 → 리셋 (+배수/정지/찰음·강음). ★2026-08-15부로 **마개 위치(HS1~5)에 의한 모드 선택·전환·정지는 `mode_arbiter`가 담당**(§0.6). 남은 공백은 **단계 간 자동 연결**(모음 완료 → 동작 자동 전이, 처리횟수 기반 자가/살균 자동 진입) — 이는 마개 조작이 아니라 시나리오 완료 이벤트로 넘어가는 부분이라 별건.
- ⚠️ **시퀀스 타이밍 엔진**: 모음/동작 내부에 서브-FSM 타이머로 구현됨(CW/정지/CCW, 분/초 마커). 단, 재사용 가능한 공용 엔진으로 추출되진 않음(각 시나리오가 자체 보유).
- ✅ **명령 입력 디코드 — 구현됨(★2026-08-15)**: `mode_arbiter.c`가 U24 HS1~5(마개 위치)를 모드와 무관하게 상시 디코딩 → 강음/모음/정지/배수/동작 명령으로 변환. 정확히 1비트만 유효 + 3샘플 디바운스 + 전이 에지 판정. 정지 계열(HS3·전채널 미인식·다중 인식)은 `jungji`로 위임.
- ⚠️ **처리 횟수 카운터**: 동작 완료 시 `g_dongjak.cycle_count` 증가 구현. 단 5회 후 자가세척 / 6회 후 살균 **자동 진입 연결은 미구현**.
- ❌ **알림/음성 상태 안내** 프레임워크(현재 비프만).

### 4.2 1단계 — 모음(헹굼) ★구현됨 (벤치 확정 대기)
> 구현: [moeum.c/.h](moeum.c). HW 매핑은 [사용자_시나리오 §4.1.1](사용자_시나리오_검토정리.md) 참조.
- ✅ 드라이버 준비: 배수문(U5)·급수밸브(VALVE_DRY_IN)·교반(M2)·도어 홀 리미트·수위 EXTI **모두 존재**.
- ✅ **상태머신 구현**: `MOEUM_IDLE→DOOR_CLOSE→FILL→FILL_EXTRA→STIR→DRAIN_OPEN→DRAIN_WAIT→DONE`(+`ERROR`). `Moeum_MotorTick`(1ms) 소유, `Moeum_SenseTick`(100ms) 센서.
- ✅ **수위센서(PF6/PF7) → 급수 정지**: 감지 후 2초 추가급수(`MOEUM_FILL_EXTRA_MS`) 후 VALVE_DRY_IN(PB13) OFF. *(감지 기본=EXTI 에지, 레벨 폴백은 `MOEUM_WATER_USE_LEVEL` opt-in)*

- ✅ 배수문 닫힘(W-HALL-CLOSE PF3)/열림(W-HALL-OPEN PF4) 인식 → 모터 정지, 열림 후 **1분 뒤 교반 정지**(`MOEUM_DRAIN_STIR_MS`).
- ✅ 안전 타임아웃(도어·급수 미도달 → `MOEUM_ERROR` 안전정지) — 스펙 외 placeholder.
- ✅ **4.5 비상정지(투입구 개방)**: ★2026-08-15부로 **중재자+jungji가 담당**(§0.6). 마개가 모음 위치를 벗어나 어느 홀도 인식되지 않으면(3샘플) `JUNGJI_SRC_HS_LOST` 비상정지 → 전 액추에이터 정지(교반 BLDC는 **단락제동**) → IDLE. HS3(정지) 위치로 돌리면 동일하게 정지 + 대기 모드 복귀. 시나리오 내부 `lid_guard`는 `MOEUM_HS_TRIGGER_INTERNAL=0`으로 비활성(이중 처리 방지). 정지버튼(3초)은 `Moeum_RequestStop()`/`g_jungji.dbg_stop_req` 훅(멤브레인 미연동 대기).
- 🔲 **벤치 확정 필요**: 수위 극성/에지(§5-1)·도어 리미트 극성(하드웨어결정 §2-1)·교반/도어 RPM·듀티·타임아웃 값. *(HS2 시작채널은 확정 — `tb_hallsensor` 라벨 검증 완료)*

### 4.3 2단계 — 동작(건조·분쇄·배출) ★구현됨 (벤치 확정 대기)
> 구현: [dongjak.c/.h](dongjak.c). **★기준 원본: `doc/R1/zerogeo_scenario.docx`([2단계] 동작, 2026-07-30)** — 사용자_시나리오_검토정리.md와 타이밍이 다르며 docx가 최신·우선.
> 시간 마커는 **홀 감지(시나리오 시작) 절대시간** 기준(110/120/130/135분).
- ✅ **상태머신 구현**: `DJ_IDLE→RINSE1_*(6)→RINSE2_*(6)→HEAT→COOLDOWN→BIN_CHECK→DISCHARGE→DONE`(+`ERROR`/`ABORTED`). 헹굼 2회는 고정 언롤(잔수배수는 2차 DRAIN 90초에 흡수, 별도 DRAIN_RESIDUAL 없음). `Dongjak_MotorTick`(1ms) 소유 + `Dongjak_SenseTick`(100ms) 센서. 건조 구간은 히터/교반/분쇄/수증기/팬 **동시 제어**.

- ✅ **히터 히스테리시스**: **117℃↑ OFF / 114℃↓ ON** (+210℃ SW 보조; 초기 급승온은 60/80℃ HW 바이메탈 보조). 써미스터 에러 시 유지. *(신스펙 항목5-A, 2026-08-15)*

THERM2=CH1/PC1 추가(`DJ_COOL_USE_THERM2=1`, `temp2_d10`/`temp2_valid`), 보수적(A안: 써미스터 에러 시 '안 식음'). 바이메탈은 `DJ_COOL_USE_BIMETAL80=1`, 진입 시 stale 엣지 클리어. (2026-08-16 바이메탈 OR / 2026-08-17 THERM2 AND 추가)

HEAT 구간 한정(신스펙 요구2). 스텝 페이싱: STEP1 run 3ms(333PPS)/start 10ms, **STEP2 전용 보수화 run 6ms(167PPS)/start 20ms(50PPS)** + 램프 40스텝. **STEP1 개방 완료 후 코일 해제(`DJ_STEP_RELEASE_DUCT_ON_OPEN`)** — DJ_HEAT는 분쇄·교반 BLDC가 같은 24V 레일을 쓰므로 STEP1 홀딩전류를 없애 STEP2 탈조("진동만")를 완화. 개폐는 `DJ_DUCT_STEPS=512` **오픈루프 스텝수(리미트 센서 없음)** 로 정지. ✅ **STEP2=35BYJ46 24V 확정(2026-08-17)** — 24V/~300Ω=~80mA/phase, 발열우려 없음. 펌웨어 페이싱(167PPS run/50PPS start)은 데이터시트(100PPS 자기기동/≥500PPS pull-out) **범위 내 보수값**. 잔여 시 동시 BLDC부하 절감 검토(HW).

FAN_VAPOR와 동반 THERM3 제어에서 분리)*
- ✅ **식힘(120분)·배출(130분)**: 히터 OFF·교반 유지 → 수거통 확인 → 배출문 개방(CW, 개방 후 DC 미구동 = HW 2분타이머 구간)+교반 배출 → **TIMER-OUT(PF8) 하강엣지**(백업 SW 2분)로 **교반만 정지**하고 문은 개방 유지(`DJ_DS_HOLD`) → **135분(`DJ_T_LATCH_MS`)에 닫기(CCW) 개시** → 닫힘 리미트 → **배수부 완전 개방**. *(2026-08-17 재정의: 이전에는 TIMER-OUT에서 즉시 닫았음. 구 동작은 `DJ_DISCH_CLOSE_AT_LATCH=0`)* **배출문 리미트(THALL_OPEN/CLOSE PF5/PF2) 있음 확인**(2026-08-16) → `DJ_TDOOR_LIMIT_OPTIONAL=0`(기본, 리미트 게이팅). **리미트 미인식이어도 `DJ_ERROR`로 떨구지 않고 계속 구동**(`DJ_DISCH_DOOR_NO_TIMEOUT=1`, err_code 5/6 경로는 컴파일 제외) — 개방은 135분 백스톱이 회수하지만 **닫기는 시간 상한 없음(정지요청/DRV8871 열보호만)**. ⚠️ 개폐 방향(`TDoor_Open`=CW 개방/`TDoor_Close`=CCW 닫힘, 임시 정의)·THALL 극성(`DOOR_LIMIT_ACTIVE_HIGH`) 벤치 확인 필요 — `disc_open_ms`/`disc_close_ms` 실측치로 판정.
- ✅ **에러 복구·코드**: `DJ_ERROR` 진입 시 `err_code`(`DjErrCode` 1~7: 헹굼CLOSE/FILL/OPEN·건조DOOR·배출OPEN/CLOSE/WOPEN) 기록. **복구 경로**: ① `g_jungji.dbg_stop_req=1`(전역 정지 — `Jungji_Tick`이 모드/`dbg_disable` 무관 상시 실행→`Dongjak_Abort()`, **벤치서 가장 확실**) ② `Dongjak_RequestStop()`/`dbg_force_stop`/`err_clear_req=1`(동작 모드 tick 필요) ③ 정상모드 마개 '정지'(HS3)→모드전환→Abort. 모두 액추에이터 정지 유지 후 `DJ_IDLE` 복귀. *(기존: ERROR 고정·복구 불가. ★주의: 벤치서 `g_modearb.dbg_disable=1`이면 STOP 홀 무시되므로 ①/②로 복구)*
- ✅ **배출 전 수거통 확인**: 처리횟수(`cycle_count`)+분말높이(fill%) 판정, 미충족 시 대기(음성 안내 TODO).
- ✅ **4.5 비상정지(투입구 개방)**: ★2026-08-15부로 **중재자+jungji가 담당**(§0.6). 마개가 동작 위치를 벗어나면 `JUNGJI_SRC_HS_LOST`, HS3으로 돌리면 `JUNGJI_SRC_HS_STOP` → 전 액추에이터 정지(분쇄·교반 BLDC는 **단락제동**), **고온이면 냉각팬 유지 식힘을 `jungji`가 이어받는다**(시나리오는 즉시 IDLE — DJ_ABORTED 경유 시 모드 전환에서 냉각이 끊기기 때문). 시나리오 내부 `lid_guard`/`DJ_ABORTED` 진입 경로는 `DJ_HS_TRIGGER_INTERNAL=0`으로 비활성이며, `Dongjak_RequestStop()`/`dbg_force_stop`으로는 여전히 `DJ_ABORTED`에 들어갈 수 있다.

### 4.5 4단계 — 살균세척
- ❌ **6회 처리 후 → 소비자 "세척 버튼" 선택 시** 진입(자동 아님). 안내 5초×3회.
- ❌ 급수→가열→교반/분쇄 반대회전→**100℃ 5분 유지**→**배수구 30초 배수**→리셋 전체 시퀀스. (이전판 "수거통 배출·10분 끓임"은 폐기)

### 4.6 배수 / 4.7 찰음·강한음식 — ★연결부만 구현(2026-08-15)
> 두 모드 모두 **중재자 연결·모드 전환·API 스텁까지는 완료**되어 마개를 HS4/HS1로 돌리면 해당 모드로 전환되고 `*_Start()`까지 호출된다. **시퀀스 본체는 의도적으로 비어 있다** — 파라미터가 확정되지 않은 상태에서 액추에이터를 돌리는 것보다 아무것도 안 하는 편이 안전하기 때문. `g_baesu.select_count`/`g_kangeum.select_count`로 선택 여부만 관찰 가능.
- ⚠️ **배수(HS4, [baesu.c](baesu.c))**: 배수 보조 15RPM 정5초/정지5초·역5초/정지5초 약 3분(뚜껑 닫으면 중지) — **미구현**. 최소 구성은 "배수문(WDoor) 개방 + VALVE-DRAIN-CLN(PB14) 개방 유지, 마개가 배수 위치를 벗어날 때까지". 종료가 시간이 아니라 **마개 위치**라는 점이 다른 시나리오와 다르고(중재자가 이탈을 이미 잡아줌), `Baesu_Abort()`에서 **문을 닫을지 열어둘지 정책 미확정**.
- ⚠️ **찰음/강음(HS1, [kangeum.c](kangeum.c))**: 보정 프로그램(밥 과다·떡·게껍데기) — **미구현**. 문서에 "강음(반복 2회)" 언급만 있고 분쇄 RPM/토크·반복 횟수·온도 프로파일 **파라미터 전부 미정**(1차 기본 프로그램 테스트 후 업그레이드 예정). 동작 시나리오의 분쇄 구간을 재사용하고 RPM/반복만 바꾸는 형태가 유력.

### 4.8 모터 부하 해소 (§5.2) — ★R1 하드웨어 착수 가능
- ⚠️ DC 전류센싱 3채널 드라이버(`dc_current`) 존재. **임계·채널매핑 확정 후** "과부하→반대회전 최소 4회→정지·에러멘트" 로직 구현 가능.

### 4.9 테스트/AS 모드
- 🚫 멤브레인 "모터선택" 기반 정식 UI(3초 진입→모터선택→정/역 확인) — **2026-08-18 폐지**(버튼 제어 미사용). 키패드는 개발자용 `tb_tca9554` 테스트벤치 전용으로만 남는다.
- ❌ 설정값 EEPROM 저장(SPI1 핸들만 존재).

## 8. 요약

- **완성**: 전 드라이버(BLDC 폐루프·도어+홀리미트·리프트PWM·스테퍼·팬·밸브·센서·DC전류·통신·키패드·비프) — R1 동기화 완료, 개별 구동 가능.
- **시나리오 구현(2개)**:
  - **1단계 모음**([moeum.c](moeum.c)) — 닫힘→급수→수위+2초→교반 22사이클→배수개방→1분 후 정지.
  - **2단계 동작**([dongjak.c](dongjak.c), 원본 `doc/R1/zerogeo_scenario.docx`) — 헹굼2회→잔수배수→건조(히터 히스테리시스+교반+분쇄 프로파일+수증기+팬 동시)→110분 2000역회전→120분 식힘→수거통확인→130분 배출→배수부 개방.
- **입력/모드 계층 ★2026-08-15 신규**: [mode_arbiter.c](mode_arbiter.c)가 **마개 위치 홀(HS1~5)을 모드와 무관하게 상시 디코딩**해 모드를 결정한다 — 이전에는 트리거가 자기가 선택해야 할 모드 안에 갇혀 디버거로만 전환이 가능했다(§0.6). 정지는 [jungji.c](jungji.c)로 단일화(부하 17종, BLDC 단락제동, 잔열 냉각 인계). 강음/배수는 **연결부만** 있는 스텁([kangeum.c](kangeum.c)/[baesu.c](baesu.c)).
- **공백**: **3·4단계(자가세척·살균세척)**, 단계 간 자동 전이(모음↔동작↔자가/살균), 강음·배수 시퀀스 본체, DC모터 부하 해소, 음성 안내, 사용자/원격 UI.
- **확정 선행**: [하드웨어결정_잔여항목.md](하드웨어결정_잔여항목.md) §1~3 (DC전류·OSC리맵·극성·써미스터 채널·스테퍼 역할·팬 역할) + 신규 2건(`MODEARB_CONFIRM_SAMPLES`·`JUNGJI_BRAKE_MS`). *U24 홀 의미는 확정됨.* 안전 락(80/60℃·210℃·배출 2분 타이머)은 **HW 처리**이며 FW는 감시/구동만.
- 즉, **"부품은 R1로 다 움직이고, 1·2단계 레시피 + 마개로 고르는 입력 계층까지 나왔다 — 벤치 검증 후 3·4단계·단계 자동전이로 확장"** 이 현 상태다.
