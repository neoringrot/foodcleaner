## 0. 한 줄 결론

**드라이버(HAL 추상화) 계층은 거의 완성되어 있으나, 시나리오를 실현하는 "제어·상태머신 계층"은 아직 존재하지 않는다.** 현재 펌웨어는 부팅 → 드라이버 초기화 → (1) 센서 폴링 태스크 + (2) 디버거 플래그로 개별 모터를 돌려보는 테스트벤치 태스크, 두 개만 동작한다. 4단계 공정·안전 인터록·음성 안내·모드 전환 로직은 미구현이다.

## 1. 현재 코드 아키텍처

```
main.c
  └ 드라이버 초기화: Lift / WiFi / BLE / Membrane / LM4871(부팅 비프)
  └ FreeRTOS 시작

freertos.c — 태스크 2개
  ├ StartDefaultTask (100ms 주기)
  │    · Distance(수거통) / Thermistor×3 / HallSensor×7 폴링 → 전역변수 갱신
  │    · Membrane_Poll() (키→LED 토글만)
  └ StartMotorTask (1ms 주기)
       · TB_DRV8871 / TB_StepMotor / TB_DRV8306 / TB_Lift 테스트벤치 폴링
       · 디버거에서 tb_*_enable 플래그를 켜야 모터가 돈다 (자동 시퀀스 없음)
```

- **계층 구성**: `Interface/`(gpio_ctrl·adc_ctrl 명명형 접근) → `Devices/`(장치별 드라이버) → `Testbench/`(디버거 수동 구동). **그 위의 "애플리케이션/시나리오" 계층은 비어 있음.**
- 드라이버 소스 전체에 `TODO/FIXME/stub` 마커 없음 → 드라이버는 완성도 높음. 미검증 항목은 (a) 도어/리프트 **회전 방향 부호**(벤치 확인 필요), (b) DRV8306 **RPM↔duty 캘리브레이션 상수**(placeholder)뿐.

## 3. 시나리오 단계별 미구현 항목

> 공통: **전 단계를 묶는 상태머신·시퀀서가 전무**하다. 아래는 각 단계 실현에 추가로 필요한 로직.

### 3.1 공정 전체 (프레임워크)
- ❌ **메인 상태머신**: 대기 → 1단계 모음 → 2단계 동작 → 3단계 자가세척 → 4단계 살균세척 → 리셋. (배수/정지/강음 모드 포함)
- ❌ **명령 입력 디코드**: 조작부 홀센서(마개 위치: 강음/모음/정지/배수/동작) → 명령 변환. 현재는 `g_hall_mask` 원시 비트만 존재.
- ❌ **시퀀스 타이밍 엔진**: "정회전 5초 / 역회전 5초 / 2분 30초 반복" 등 시간 기반 스텝 실행기. (테스트벤치는 디버거 수동 구동뿐)
- ❌ **처리 횟수 카운터**: 6회 완료 → 7회째 살균세척 자동 진입.
- ❌ **알림/음성 상태 안내** 프레임워크.

### 3.2 1단계 — 모음(헹굼)
- ⚠️ 배수문 닫기(WDoor) · 급수(밸브 ON)까지 드라이버는 준비됨.
- ❌ **수위센서 감지 → 급수 정지** 연동(WATER_SEN EXTI 소비).
- ❌ **교반 정·역 2분30초 시퀀스**(DRV8306 M) 실행 로직.
- ❌ 배수 시작~문 닫기 타이밍 제어, 기본 1회/반복 횟수 제어.

### 3.3 2단계 — 동작(건조·분쇄·배출) ★핵심 공백
- ❌ **히터 온도 프로파일 제어**: 25분→130℃, 60분→150℃, 90분→170℃, 120분→195℃의 시간대별 목표를 써미스터로 ON/OFF 제어. (현재 `HT_POWER`는 단순 ON/OFF만)
- ❌ **바이메탈 게이팅 소비**: 50℃/80℃/200℃ 임계에 따른 분쇄·배수 동작 허용/차단(EXTI 플래그 소비).
- ❌ **분쇄 BLDC 프로파일**: 50℃↑ 기동, 80℃↑ RPM 램프(1500→600→1000→1500), 정·역·정지 반복 시퀀스.
- ❌ **교반 BLDC 프로파일**: 정회전 5초/2초 정지/역회전 반복(120분).
- ❌ **수증기 배출 제어 루프**: 100℃ 도달 → 계폐(스테핑)+팬 ON → 80℃까지 배출 → 닫고 반복.
- ❌ **건조 종료 냉각**(히터 OFF + 교반 10분) 및 배출 트리거.
- ❌ **배출 전 안전 체크**: 수거통 유무(홀) + 처리 횟수 + 분말 높이(거리센서) 판정 → 미충족 시 음성 안내·대기.
- ❌ **배출부 문 2분 개방 → 닫힘 → 리셋** 시퀀스.

### 3.4 3단계 — 자가세척
- ❌ "음식물 없는 상태에서 1단계와 동일 동작 1회" 재사용 호출 로직(상태머신 분기).

### 3.5 4단계 — 살균세척
- ❌ 6회 처리 후 진입, 수거통 비움 안내(5초×3), 급수→가열→50℃ 배수 30%→100℃ 10분 끓임→20분 냉각→수거통 배출→리셋 전체 시퀀스.
- ❌ **살균수 수거통 배출 흐름**(배수 아닌 통 배출) 및 관련 음성 안내.

### 3.6 테스트/AS 모드 (로직도 5p)
- ❌ **멤브레인 "모터선택" 기반 UI**: 3초 누름→모터 선택→정/역회전 확인, RPM 가변(±10%) 설정·저장. (현재는 개발자용 디버거 플래그 테스트벤치로만 가능, 최종 사용자 UI 아님)
- ❌ 설정값 **EEPROM 저장**: `SPI1_EEPROM_CS`(PC4)·`FRAME_WP`(PE15) GPIO 핸들은 있으나 EEPROM 드라이버·파라미터 저장 로직 없음.

## 4. 하드웨어/GPIO 매핑 갭 (설계 확인 필요)

시나리오상 필요하나 펌웨어에 **핸들 자체가 없거나 매핑이 불명확**한 항목:

1. **기억 래칭 릴레이(불법배출 방지 핵심)** — `gpio_ctrl`에 SET/RESET 출력 핸들 없음. 불법배출 방지의 핵심 소자인데, MCU가 이 릴레이를 제어/감지하는지, 아니면 순수 하드웨어 래치(바이메탈+릴레이 자기유지)로만 동작하는지 **설계 경계 확정 필요**. (시나리오 §5: 배출문 닫힘 시 리미트 스위치 신호로 RESET)
2. **배수/배출 문 리미트 스위치** — 전용 GPIO 없음. 후보는 `LEAD_SW`(PF5), 홀센서(HS1~7), `WATER_SEN1/2`. **어느 신호가 문 닫힘 감지인지 매핑 미정.**
3. **조작부 홀센서 채널 부족** — 펌웨어 `hallsensor`는 **7채널(U10 HS1~7)**. 시나리오/사양서는 조작부 5(강음/모음/정지/배수/동작) + 개별 4(수거통·교반가이드·에어·승강) = **9채널 필요**. **2채널 부족** → 확장 방식 확인 필요.
4. **바이메탈 채널 수 상충** — 펌웨어 EXTI 5채널(`BIMETAL1~5`) vs 사양서 6~7개. 수량·용도(200℃/80℃/50℃ 구분) 매핑 확정 필요.
5. **HS 채널별 물리 대상 미문서화** — `hallsensor.h`는 HS1~7이 각각 무엇을 감지하는지 기록 없음. 스키매틱/시나리오로 채널↔기구 매핑표 작성 필요.
6. **음성 안내 경로** — 스피커는 비프(사각파)만 가능. 시나리오의 다수 음성 멘트("수거통을 비워주세요" 등) 구현 방식(내장 음원 재생 vs 휴대폰/앱 연동 TTS) **미정**.
7. **써미스터 3채널 용도 배정** — 히터 온도(사양서 3개) vs 처리통 내부 온도(사양서 별도 1개, DG3C332HF) 구분이 펌웨어에 없음. 3ch가 어디에 붙는지 매핑 필요.

## 4-B. 매핑 확정 · 불일치 · 확인필요 (2026-07-28 세션 결정, 세션 인계용)

> §4의 갭들에 대한 사용자 결정 사항. 코드/네트리스트(`sch/netlist final.NET`, `gpio_ctrl.h`, `drv8306.c` 등) 대조 완료. **다음 세션은 아래 "확인필요 8건"을 먼저 확정한 뒤 매핑 확정표를 코드에 반영할 것.**

### (A) 확정된 결정 — 코드/네트리스트와 일치 검증 완료 ✅

| **공기배출 스테핑** | **STEP1** (Q5~Q8, PD8~PD11) | net STEP1-M1~M4 |
| **공기흡입 스테핑** | **STEP2** (Q9~Q12, PD12~PD15) | net STEP2-M1~M4 |
| **건조통 급수 솔밸브** | net **`VALVE-DRY-IN`** → `GPIO_OUT_VALVE_DRY_IN`(PB13) | 네트리스트 확인 |
| **배수구 세척 솔밸브** | net **`VALVE-DRAIN-CLN`** → `GPIO_OUT_VALVE_DRAIN_CLN`(PB14) | 네트리스트 확인 |
| **수증기 배출 팬** | net **`FAN-VAPOR`** → `GPIO_OUT_FAN_VAPOR`(PB15) | 네트리스트 확인 |
| **건조통 급수동작 + 수위체크** | net **`WATER-ON`**(PF8), **`WATER-SEN1`**(PF6 EXTI), **`WATER-SEN2`**(PF7 EXTI) | 네트리스트 확인 |
| **히터 제어** | net **`HT-POWER`** → `GPIO_OUT_HT_POWER`(PA12) | 네트리스트 확인 |

### (B) 불일치 1건 — 정정 필요 ⚠️

- **환풍 팬을 "Q19"로 지정한 것은 오류.** net **`FAN-EXHAUST`**(PG2, `GPIO_OUT_FAN_EXHAUST`)를 구동하는 트랜지스터는 **Q25**(DTC144EET1G)다. **Q19는 무관한 전원 P-FET**(FDN5618P, 24V 라인). → **net 이름 `FAN-EXHAUST`는 정확하므로 그대로 사용, 부품번호만 Q19→Q25로 정정.**

### (C) 다음 세션에서 확정할 것 — 확인필요 8건 ❓

결정에 따라 파생 공백이 생기므로 코드 착수 전 아래를 확정해야 함.

1. **수거통 유무 감지 수단** — 홀센서(수거통 유무)를 비웠는데 시나리오 **배출 전 안전체크(2단계-7, 4단계)**가 이에 의존. → 거리센서(GP2Y0A41, `distance` fill%)로 "유무+높이" 겸용 판정할지, 체크를 생략할지 결정.
2. **하드웨어 래치 RESET 트리거** — 시나리오 §5의 래치 해제는 "배출문 닫힘 리미트 스위치" 신호였음. 리미트 제거 + 순수 HW 래치에서 **무엇이 래치를 리셋**하는지(전원 리셋/별도 접점/기타) 정의 필요. "재헹굼 활성화" 조건이 여기에 결부됨.
3. **써미스터 3채널 역할 배정** — 펌웨어는 NTC 3ch(`THERM1/2/3`)뿐. **① 히터 온도 프로파일** + **② 처리통 내부 100℃(수증기 배출)** 둘 다 온도 필요. 사양서상 처리통 내부 온도센서(DG3C332HF)는 별도 부품이나 펌웨어엔 없음. → 3채널을 각각 어디에 배정할지.
4. **에어공급 위치 피드백** — 홀센서(에어공급) 비움 → 흡입 스테핑(STEP2)은 **오픈루프(스텝 카운트)** 제어만 가능. 원점/위치 피드백 없이 충분한지 확인.
5. **바이메탈 배선/엣지** — 5개가 **220V 차단 경로(HW)와 MCU EXTI 감지선에 동시 연결**되는지 확인. 펌웨어 EXTI는 **falling-edge만** 설정 → "200℃ open(접점 열림=상승엣지)"은 인터럽트가 아닌 **레벨 읽기(`gpio_ctrl_exti_read`)**로 판정 권장.
6. **배수부 급수라인 수위센서(사양서 23번)** — `WATER-SEN1/2`는 건조통 급수용으로 배정됨. 이 별도 수위센서는 **드롭인지 별도 라인 필요인지** 확정.
7. **`LEAD_SW`(PF5, 리드 스위치) 용도** — 미배정. 시나리오 "투입구 마개 개방 감지"(대기 중 마개 열림 시 비상 안내) 용도 여부 확인.
8. **RPM 캘리브레이션** — 분쇄=M1(204W)/교반=M2(41.8W) 배정에 따라 DRV8306 RPM↔duty 상수는 **인스턴스별로 각각** 실측 필요(현재 공용 placeholder).

## 5. 우선순위 제안 (구현 로드맵 관점)

| 순위 | 항목 | 근거 |
|---|---|---|
| 1 | 메인 상태머신 + 시퀀스 타이밍 엔진 골격 | 모든 단계의 토대. 없으면 개별 드라이버가 겉돎 |
| 2 | 조작부 홀센서 → 명령 디코드 | 사용자 입력 진입점 |
| 3 | 히터 온도 프로파일 제어 + 바이메탈/써미스터 안전 인터록 | 2단계 핵심, 안전 직결 |
| 4 | 급수(수위센서 연동)·배수·문 개폐 시퀀스 | 1·2단계 기본 동작 |
| 5 | 교반/분쇄 BLDC 프로파일 + RPM 캘리브레이션 | 2단계 핵심. 캘리브레이션은 테스트벤치 활용 |
| 6 | 수증기 배출 루프 / 냉각 / 배출 안전체크 | 2단계 후반 |
| 7 | 불법배출 방지 인터록(래칭 릴레이 경계 확정 후) | 설계 확인 선행 필요 |
| 8 | 3·4단계 시퀀스 + 처리횟수 카운터 | 상위 골격 재사용 |
| 9 | 음성 안내, 멤브레인 UI/RPM설정, EEPROM 저장, 원격(WiFi/BLE) | 부가 기능 |

## 6. 요약

- **완성**: 전 드라이버(모터·도어·리프트·스테퍼·팬·밸브·센서·통신·키패드·비프) — 개별 장치 구동 가능.
- **공백**: 이들을 엮는 **시나리오 제어 계층 전체** — 상태머신, 타이밍 시퀀서, 명령 디코드, 히터 온도제어, 안전 인터록, 배출 판정, 음성 안내, 처리횟수/모드 관리, 사용자·원격 UI.
- **설계 확정 필요(코드 착수 전)**: 래칭 릴레이 제어 경계, 리미트 스위치/홀센서/바이메탈 채널 매핑, 홀 채널 수 부족(7 vs 9), 써미스터 용도 배정, 음성 구현 방식, M1/M2↔분쇄/교반 배정.
- 즉, **"부품은 다 움직이는데, 아직 레시피(공정 제어)가 없다"** 가 현 상태다.
