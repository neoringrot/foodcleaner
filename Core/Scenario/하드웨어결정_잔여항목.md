## 0. 현재 상태 요약

R1 회로 기준으로 **핀맵·.ioc·펌웨어 골격 동기화는 완료**됐다. CubeMX generate 반영,
드라이버/인터페이스 계층까지 수정 완료(빌드 정합 확인, 실컴파일은 CubeIDE에서 필요).
아래는 그 위에서 **하드웨어 값/극성/정책을 확정해야 코드가 실동작으로 완성**되는 잔여 항목이다.

### 이미 확정되어 반영 완료된 결정 ✅
| 결정 | 반영 위치 |
|---|---|
| PF8/PF9/PF10 = **입력**(TIMER-OUT, HALL-INT1/2) | `gpio_ctrl` EXTI, `stm32f1xx_it.c` |
| PF2~PF5 = **도어 홀센서**(바이메탈 아님) | `gpio_ctrl` GPIO_EXTI_[TW]HALL_[OPEN/CLOSE] |
| LIFT = **TIM4 HW PWM**(PB8/PB9, 20 kHz) | `lift_motor.c` DRV8871 핸들 |
| 클럭 **HSI 유지** / 도어-EN = **PE3·PE4**(PD01 리맵 폐기) | `main.h` `o_EN_DOOR_TRASH`=PE3, `o_EN_DOOR_WATER`=PE4 |
| Hall 확장기 = **U24 0x3B, HS1~HS8**, INT=PF9 | `hallsensor.c`, `tca9554.h` |

## 1. 즉시 확정 필요 — 코드에 placeholder/가정으로 들어간 값 ⚠️

### 1-1. DC 전류센싱 — **RESOLVED [2026-08-09]** (R1 NET 추적 + 모터 데이터시트)
> ✅ 채널↔모터 매핑·션트·게인·환산·임계 모두 확정, `dc_current.c/.h` 반영 완료.

- **채널↔모터 매핑 (R1 NET: op-amp IN+ 션트 → DRV8871 → IN핀 TIM채널 역추적)**

  | ch | ADC핀 | op-amp | DRV8871 | 모터 |
  |---|---|---|---|---|
  | `DC_CURR_LIFT` | PC5/IN15 | U4 | U6 | 리프트 |
  | `DC_CURR_TDOOR` | PB0/IN8 | U5 | U9 | 쓰레기도어 |
  | `DC_CURR_WDOOR` | PB1/IN9 | U25 | U11 | 급수도어 |

- **센싱 체인 (3채널 동일)**: 10mΩ 션트(WSHP2818R0100) → LM321LV 비반전 게인 **×2**(1+1K/1K) → 470Ω+1nF RC → ADC. **= 20mV/A**(≈24.8 code/A, ≈40.3mA/code)
- **모터 `JK30ZYT-5840-577`**(24VDC, 감속비577): 무부하 0.2A / **정격 1A** / **구속 4.5A**
- **트립 임계**: `DC_CURRENT_TRIP_MA = 3000`(3.0A, 정격+인러시 위, 구속 아래) → 걸림감지. 코드환산 ≈74. 필요시 헤더 상수만 조정
- **검산**: 1A→1007mA, 4.5A→4512mA(오차 <2%)
- **주의(잔여, 벤치)**: ① 분해능 coarse(40mA/code) — median-of-5로 완화, 스톨감지엔 충분 ② PWM(20kHz) 중 전류 chopping 리플 존재 → median 필터로 완화, 필요시 샘플수↑ ③ 각 op-amp 게인저항(U5:R162, U25:R166) GND쪽 1K 대칭 가정(U4는 R158=1K 확인) — 벤치 실측 권장
- **연계 시나리오**: `사용자_시나리오_검토정리.md` §5.2 "모터 부하량 체크 및 걸림 해소"
- **남은 것(정책)**: 과전류 검출 시 정지/역회전/재시도 시퀀스 → §3-2 참조

### 1-2. Hall 확장기(U24) 주소 스트랩 · 극성 — **RESOLVED [2026-08-14/15]**
- **현재 코드**: `hallsensor.c` → `TCA9554_U10_ADDR = 0x3B`(A2A1A0=011), `HALLSENSOR_ACTIVE_HIGH=0`(active-low)
- ✅ 1. 주소 0x3B 확인 — U24 8채널(HS1~HS8) 버스 동작 정상.
- ✅ 2. active-low(오픈드레인, 자석=LOW) 확인 — 극성반전 레지스터로 정규화, `HALLSENSOR_ACTIVE_HIGH=0` 유지.
- ✅ 3. **HS 의미 확정** (`tb_hallsensor`로 8채널 전수 검증, HS1~HS3 초기 단락은 리워크로 해소):
  | 채널 | U24 | 의미 | 소비처 |
  |---|---|---|---|
  | HS1 | P0 | 마개=**강음** | `mode_arbiter` → `APP_MODE_KANGEUM`([kangeum.c](kangeum.c), 스텁) |
  | HS2 | P1 | 마개=**모음** | `mode_arbiter` → `APP_MODE_MOEUM` + `Moeum_Start()` |
  | HS3 | P2 | 마개=**정지** | `mode_arbiter` → `Jungji_Request(HS_STOP, EMERGENCY)` |
  | HS4 | P3 | 마개=**배수** | `mode_arbiter` → `APP_MODE_BAESU`([baesu.c](baesu.c), 스텁) |
  | HS5 | P4 | 마개=**동작** | `mode_arbiter` → `APP_MODE_DONGJAK` + `Dongjak_Start()` |
  | HS6 | P5 | 교반원점 | ❌ **소비 로직 미구현** (§3-5) |
  | HS7 | P6 | 수거통 유무 | ❌ **소비 로직 미구현** — 현재 배출 판정은 거리센서 fill%만 사용 |
  | HS8 | P7 | 리프트 하단 | ❌ **소비 로직 미구현** (§3-5) |
- **참고**: 보드 U8/U9 스왑 이슈(0x39=keypad SW, 0x38=LED) 별건 존재 — 메모리 `tca9554-u8-u9-swap`

### 1-3. 도어-EN 핀 → **PE3/PE4 [펌웨어 RESOLVED 2026-08-09]** · ⚠️ HW 액션 잔여
- **펌웨어 확정·반영 완료**: `o_EN_DOOR_TRASH` = **PE3**, `o_EN_DOOR_WATER` = **PE4**(`main.h` 확인됨). 무효했던 `__HAL_AFIO_REMAP_PD01_ENABLE()`도 `main.c`에서 제거 완료.
- **원인 요약**: R1 NET 원본이 도어-EN을 핀23/24(**OSC_IN/OSC_OUT**)에 배선했는데, LQFP144에서 OSC핀은 GPIO 불가이고 PD0/PD1과도 별개 전용핀이다(초기 검토가 OSC→PD0/PD1로 잘못 alias했던 것을 정정). 도어-EN 2핀 외 나머지 67개 포트는 R1 NET과 완전 일치.
- **남은 HW 액션**: R1 회로도/PCB에서 TRASH-DOOR-EN→**PE3**, WATER-DOOR-EN→**PE4** 재배선(개정 릴리스).
- ⚠️ **확인 필요(모순)**: 도어 모터 U5/U7은 이미 **HW 검증완료**로 기록돼 있다(개별기능검증 항목 9·10). EN이 연결돼야 구동되므로 **실물 보드가 이미 PE3/PE4로 되어 있는지** 확인할 것 → [HW미검증_항목.md](HW미검증_항목.md) §3.

## 2. 벤치 확인 필요 — 극성/방향 ❓

### 2-1. 도어 리미트 홀 극성 — **RESOLVED [2026-08-10]** (R1 NET 회로 확정)
> ✅ 회로 추적으로 **active-low 확정**, 코드 반영 + 반전 가능하게 매크로화 완료.
- **회로 근거(R1 NET)**: 5개 홀넷 모두 **10K 풀업→3P3V**(R13/R40/R151/R32/R83), 센서 커넥터 3선식(J3: VCC/OUT/GND) = **오픈드레인 홀 → active-low**(자석=LOW). EXTI IT_FALLING이 "리미트 도달 순간"과 일치.
- **반영**: `tdoor.c`/`wdoor.c`의 `AtOpen/AtClose`를 `DOOR_LIMIT_ACTIVE_HIGH`(기본 0=active-low) 매크로 기준으로 정리. 센서 변형 시 **헤더 매크로 한 줄(0→1)** 로 전체 반전.
- 매핑: PF5=T-HALL-OPEN, PF2=T-HALL-CLOSE, PF4=W-HALL-OPEN, PF3=W-HALL-CLOSE
- **추가 인지**: W-HALL-CLOSE(PF3)는 HW NOR 게이트 U13(SN74LVC1G02)로 `Bimetal-80`과도 논리조합(솔더브릿지 경유) — MCU 직접읽기와 별개인 하드웨어 안전 인터록. 용도/소비 확인은 별도(§3 계열).
- **남은 것(벤치)**: 실제 자석 접근 시 LOW 확인(형상/장착), 반대면 매크로만 반전. → [HW미검증_항목.md](HW미검증_항목.md) 1-1

### 2-2. 도어/리프트 회전 방향 (미확정 유지)
- `tdoor.h`/`wdoor.h`/`lift_motor.h`: Open/Close·Up/Down이 DRV8871 Forward/Reverse에 임시 매핑.
  벤치에서 반대로 움직이면 해당 .c에서 두 호출 스왑. **2-1과 반드시 같이 본다**(방향이 반대면 리미트에
  영원히 도달하지 못해 타임아웃→ERROR로 떨어진다). → [HW미검증_항목.md](HW미검증_항목.md) 1-2

### 2-3. HALL-INT2 (PF10)
- **현재**: 넷리스트상 J15(외부 U25/U26 테스트베드) 전용, 온보드 소자 없음 → 코드 미소비(정상).
- **확정**: 양산 보드에서도 PF10을 사용 안 함이 맞는지(외부 테스트 전용 유지).

## 3. 정책/제어 로직 결정 필요 — 접근자만 제공됨 ❓

아래는 하드웨어 인터페이스(읽기/제어 함수)는 완성됐으나, **언제/어떻게 쓸지(제어 정책)**가 시나리오 확정 대기.

### 3-1. 도어 리미트 기반 정지 시퀀스
- 제공: `TDoor_AtOpen/AtClose()`, `WDoor_AtOpen/AtClose()` (리미트 도달 1)
- 필요: "목표 리미트 도달 시 brake/stop" 모션 컨트롤러(개폐 시퀀스, 타임아웃, 실패처리)
- 연계: `사용자_시나리오_검토정리.md` §4.2(배출), §4.3(수거통 확인)

### 3-2. DC 전류 과부하 → 걸림 해소/정지
- 제공: `DcCurrent_IsOver()`, `DcCurrent_UpdateAll()`(과전류 비트마스크)
- 필요: 과전류 감지 시 정지·역회전(걸림 해소)·재시도·에러표시 시퀀스
- 연계: §5.2

### 3-3. 팬 3개 구동 정책 — ✅ **확정 [2026-08-17] (동작 시나리오)**
- 제공: `gpio_ctrl_on/off(GPIO_OUT_FAN_VAPOR / FAN_EXHAUST / BLDC_FAN)`
- ✅ **역할·구동 확정** (dongjak.c 구현):
  | 팬 | 핀 | 구동 정책 |
  |---|---|---|
  | **FAN_VAPOR**(방수/수증기팬) | PB15 | 수증기 루프 단독: THERM3(J23) **100℃ ON / 84℃ OFF**, 팬 먼저→STEP1/STEP2 개방. DJ_HEAT 한정 |
  | **FAN_EXHAUST**(배기팬) | PG2 | **THERM3와 분리** — 시나리오 전체(RINSE1_CLOSE~DISCHARGE) **15분 ON / 2분 OFF 독립 duty** (`DJ_FANX_ON_MS`/`OFF_MS`). *구 10초/5초 내부정화 → 15/2분 변경(2026-08-17)* |
  | **BLDC_FAN**(열 식힘팬) | PG1 | 분쇄모터 동작 중(`grind_mode≠OFF`) **30초 ON / 10초 OFF** duty (`DJ_FANB_ON/OFF_MS`) |
- 연계: §4.2 동작 단계. 상세 현황 = [구현현황_및_미구현_점검.md](구현현황_및_미구현_점검.md) 2단계 팬 항목.

### 3-4. TIMER_OUT (PF8, 555 타이머 입력) 소비 — ✅ **연동 완료 [2026-08-15 신스펙 항목8]**
- 제공: `gpio_ctrl_exti_flag_get(GPIO_EXTI_TIMER_OUT)`, `gpio_ctrl_exti_read()`
- ✅ **소비처 확정**: 배출문 개방 = HW 2분 타이머 시작 → **TIMER-OUT 하강엣지 = 2분 완료**로 배출 교반을 정지(`dongjak.c` `DJ_DS_EXPEL`). 문 닫기는 별도로 135분(`DJ_T_LATCH_MS`)에 개시.
- ⏳ **남은 것**: **핀 극성·플로팅(NOPULL) HW 미검증** → 현재 SW 2분 백업(`DJ_DISCH_STIR_SW_BACKUP=1`)을 켜 둔 상태. [HW미검증_항목.md](HW미검증_항목.md) 1-5
- 연계: `사용자_시나리오_검토정리.md` §3.2 "기억 레치 릴레이 & 딜레이 타이머"

### 3-5. HS1~HS8(U24) 소비 로직 — **HS1~5 구현 완료 [2026-08-15] / HS6~8 잔여**
- 제공: `HallSensor_Get(0..7)`, `g_hall_mask`, INT 저지연 갱신(`HallSensor_ServiceInt`)
- ✅ **HS1~HS5(마개 위치)**: [mode_arbiter.c](mode_arbiter.c)가 `HallSensor_GetMask() & 0x1F`를 **모드와 무관하게** 100ms마다 디코딩(정확히 1비트만 유효 + 3샘플 디바운스 + 전이 에지) → 모드 전환 / 정지([jungji.c](jungji.c)) 위임. 매핑은 §1-2 표.
> **HS6~HS8은 센서 자체가 ✅HW 검증완료(2026-08-15)** — 아래는 전부 **펌웨어 소비 로직 미구현**이라는 뜻이다(미검증 아님).
- ❌ **HS6 교반원점**: 교반 가이드의 원점 복귀(홈잉) 미구현. 배출 전 교반날을 특정 각도로 정렬해야 하는지 여부부터 확정 필요.
- ❌ **HS7 수거통 유무**: 현재 `DJ_BIN_CHECK`는 처리횟수(`cycle_count`)+분말높이(거리센서 fill%)만 본다. **수거통이 빠져 있어도 배출로 진행**하므로, 이 채널을 `dj_bin_check`에 물려야 안전판정이 완성된다. ← **안전 공백, 우선순위 높음**
- ❌ **HS8 리프트 하단**: 리프트 하강 정지 리미트. 현재 `tb_lift`는 시간/수동으로만 구동하며 리미트 게이팅이 없다.
- **잔여 확정 필요값(벤치)**: `MODEARB_CONFIRM_SAMPLES=3`(300ms) — 마개를 천천히 돌릴 때 통과 위치(HS3 정지/HS4 배수)가 확정되어 오트리거될 수 있음. 조작감 확인 후 상향 또는 "직전이 NONE일 때만 전환" 규칙 추가 판단.
