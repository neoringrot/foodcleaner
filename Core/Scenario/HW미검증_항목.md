## 1. 미검증 상세

### 1-1. 도어 리밋홀 WHALL/THALL (PF3 W-CLOSE / PF4 W-OPEN / PF2 T-CLOSE / PF5 T-OPEN) ⏳
- **확정된 것**: 극성은 **active-low**(R1 NET에서 5개 홀넷 모두 10K→3P3V 풀업 + 3선식 오픈드레인 홀). `DOOR_LIMIT_ACTIVE_HIGH=0`.
- **미검증**: 실제 자석 접근 시 LOW 떨어짐 · 도어 행정 끝에서 인식되는지 · **리미트 도달까지 걸리는 실제 시간**.
- **현재 FW**: `MOEUM_DOOR_LIMIT_OPTIONAL=0` / `DJ_DOOR_LIMIT_OPTIONAL=0` / `DJ_TDOOR_LIMIT_OPTIONAL=0` — **모두 정상(리미트 게이팅) 모드**로 되돌아가 있다. 즉 리밋홀이 안 잡히면 타임아웃 → `MOEUM_ERROR`/`DJ_ERROR`로 떨어진다.
- **검증 절차**: `tb_doorhall_enable=1` → 문을 손으로 여닫으며 `tb_wdoor_at_open/close`, `tb_tdoor_at_open/close`, 하강엣지 카운트 확인 → 그 다음 `tb_wdoor_enable`/`tb_tdoor_enable`로 모터 구동 중 인식 확인.
- **검증 후 액션**: ① 실측 행정시간으로 `MOEUM_DOOR_TIMEOUT_MS`(현재 30초)·`DJ_DOOR_TIMEOUT_MS`(15초) 재산정 ② §2의 배출문 무타임아웃 완화 해제 판단.

### 1-2. 도어·리프트 회전 방향 라벨 ⏳
- **미검증**: `WDoor_Open/Close`, `TDoor_Open/Close`, `Lift_Up/Down`이 DRV8871 Forward/Reverse에 **임시 매핑**되어 있다. 배출문은 `dongjak.c`에서 "개방=CW / 닫힘=CCW(역방향)"으로 임시 정의.
- **영향**: 방향이 반대면 리미트에 영원히 도달하지 못해 1-1과 함께 타임아웃 → `DJ_ERROR`. **1-1과 반드시 같이 검증**한다.
- **검증 후 액션**: 반대로 움직이면 해당 `.c`(`wdoor.c`/`tdoor.c`/`lift_motor.c`)에서 Forward/Reverse **두 호출만 스왑**.

### 1-3. 히터 HT-POWER (PA12) ⏳
- **미검증**: 트라이악 실제 구동 · 온도 추종 토글 · 210℃ 바이메탈 차단과의 협조.
- **현재 FW**: 동작 시나리오는 이미 히스테리시스로 구동한다(`DJ_TEMP_HEATER_ON/OFF_D10 = 1140/1170` = **114℃ ON / 117℃ OFF**, 신스펙 5-A). 써미스터 에러(`temp_valid=0`)면 **강제 OFF**.
- **주의**: 테스트벤치 `tb_heat`의 기본 임계는 **190/195℃**(`tb_heat_on_d10`/`off_d10`)로 시나리오와 다르다 — 폐기된 구 스펙 값이라 벤치에서 헷갈리지 말 것(디버거로 1140/1170으로 바꿔 확인 권장).
- **검증 절차**: `tb_heat_enable=1`, `tb_heat_mode=TB_HEAT_MODE_HYST` → 프로브 가열/냉각하며 `tb_heat_out` 토글 관찰. `TB_Heat_Poll()`은 `APP_MODE_TESTBENCH`에서만 핀을 잡으므로 시나리오와 충돌하지 않는다.

### 1-4. NTC 온도 절대정확도 (THERM1 PC0 / THERM2 PC1 / THERM3 PC2) ⏳
- **확정된 것**: R-T 룩업+보간(−40~200℃ ±0.1℃) **자체검증 완료**, read 동작 확인.
- **미검증**: **기준 온도계 실측 대조**.
- **영향 범위가 가장 넓다** — 히터 114/117, 분쇄 허용 65℃(=실제 80℃ 오프셋 가정), 식힘 OFF 80℃, 수증기 100/84℃가 **전부 이 값에 의존**한다. 특히 "실제 80℃ = 센서 65℃" 오프셋은 **실측으로 확정해야 할 가정**이다.
- **검증 절차**: `tb_therm_enable=1` → `tb_therm_c_d10[0..2]`를 기준 온도계와 비교(상온·80℃·114℃ 근처 3점 이상).

### 1-5. TIMER-OUT (PF8, 555 2분 타이머) ⏳
- **미검증**: **핀 극성**과 **플로팅(NOPULL) 상태**. 배출문 개방 = HW 2분 타이머 시작이라는 동작 자체도 미확인.
- **현재 FW**: 배출 교반 종료 판정에 하강엣지를 쓰고(`DS_EXPEL`), 안 오면 SW 2분으로 종료(`DJ_DISCH_STIR_SW_BACKUP=1`).
- **검증 절차**: 배출문 개방 후 2분 시점에 `gpio_ctrl_exti_flag_get(GPIO_EXTI_TIMER_OUT)`이 서는지 관찰. NOPULL로 떠 있으면 오검출 가능 → 풀 설정 재검토.
- **검증 후 액션**: 확인되면 `DJ_DISCH_STIR_SW_BACKUP=0`(TIMER-OUT만 신뢰) 판단.

### 1-6. HW 안전 인터록 (바이메탈 60/80/210℃ · 배수문 락 · 배출 래치) ⏳
- MCU 제어가 아니라 **HW 주체**라 펌웨어 검증 대상이 아니지만, **FW가 그 동작을 전제로 하고 있어** 확인이 필요하다:
  - **60℃**: 급수밸브 차단 래치 SET → 헹굼 급수가 고온에서 막히는지
  - **80℃**: 배수문 락 SET(배수문닫힘 홀 AND) + **분쇄 게이팅**(MCU HIGH AND 바이메탈 LOW) → MCU가 분쇄를 켜도 80℃ 미만이면 안 도는지
  - **210℃**: 히터 차단(바이메탈 직렬 4개)
  - **배출 래치 해제**: 배출문 리드/홀 스위치로 HW 즉시 처리
- **현재 FW가 의존하는 지점**: `DJ_COOL_USE_BIMETAL80=1` — 식힘 분쇄 OFF 판정에 **80℃ 바이메탈(PF0) 하강엣지를 센서와 OR**로 쓴다. 이 핀 동작이 미검증이므로, 오동작 시 식힘 전환이 빨라지거나(엣지 오검출) 센서 단독 판정으로 남는다.
- **W-HALL-CLOSE(PF3) 주의**: HW NOR 게이트 U13으로 `Bimetal-80`과 논리조합(솔더브릿지 경유)되어 있다 → 1-1 검증 시 **MCU 직접읽기 값과 인터록 동작을 분리해서** 봐야 한다.

### 1-7. 스테퍼 실부하 페이싱 (STEP1 냄새관로 / STEP2 흡입) ⏳
- **검증된 것**: 무부하 회전(항목 7/8), 배선·공통선(STEP1 Red / STEP2 **Yellow**), 24V.
- **미검증**: **실부하 + 분쇄/교반 BLDC 동시통전** 상태에서 탈조 없이 도는지.
- **현재 FW(보수적으로 이미 디레이팅)**: STEP1 run **3ms(333PPS)** / start 10ms(100PPS) 램프 40스텝, STEP2 run **6ms(167PPS)** / start 20ms(50PPS). 관로 개방 후 `DJ_STEP_RELEASE_DUCT_ON_OPEN=1`로 **STEP1 코일 해제**(홀딩전류를 STEP2에 양보).
- **검증 후 액션**: 여전히 탈조하면 4~5ms로 더 낮춤. 코일 해제로 관로가 드리프트하면 `DJ_STEP_RELEASE_DUCT_ON_OPEN=0`. `DJ_DUCT_STEPS=512`(완전개폐 스텝수)는 **아직 TBD 값**이라 실측 필요.

### 1-8. DC 전류센싱 게인 / 스톨 임계 ⏳
- **확정된 것**: 채널↔모터 매핑, 10mΩ 션트 + ×2 게인 = 20mV/A 환산.
- **미검증**: op-amp GND쪽 게인저항 대칭 가정(**U5:R162 / U25:R166** — U4:R158=1K만 확인됨) · 트립 임계 `DC_CURRENT_TRIP_MA=3000`(계산값).
- **FW 미구현**: 과전류 감지 시 정지/역회전(걸림해소)/재시도 시퀀스가 없다 → 기획서 4.6 "모터 부하 4회 방향전환", "부하 크면 교반 30RPM(`DJ_STIR_RPM_HILOAD`)"이 **스위칭 소스 없이 대기 중**.

### 1-9. HS7 수거통 유무 — 센서 ✅ / 소비 로직 ❌ **(안전 이슈)**
- U24 P6 센서는 2026-08-15 검증 완료. 그런데 `DJ_BIN_CHECK`는 **처리횟수(`cycle_count`) + 분말높이(거리센서 `bin_fill_pct`)만** 본다.
- 즉 **수거통이 빠져 있어도 배출문을 열고 배출한다.** `dj_bin_check`에 HS7을 물려야 안전 판정이 완성된다. `DJ_BIN_FULL_PCT=90`도 TBD 값.

### 1-10. HS6 교반원점 / HS8 리프트 하단 — 센서 ✅ / 소비 로직 ❌
- HS6: 배출 전 교반날을 특정 각도로 정렬(홈잉)해야 하는지 **요구부터 미확정**.
- HS8: 리프트 하강 정지 리미트. `tb_lift`는 시간/수동 구동만 하고 리미트 게이팅이 없다.

### 1-11. 시나리오 통합 풀런 ⏳ **(이번 변경으로 성격이 바뀐 항목)**
- 지금까지 검증된 것은 **개별 기능(tb_\*)** 이고, 모음 1사이클·동작 135분 **연속 풀런은 미실시**다.
- **2026-08-18부터 `DJ_TEST_FAST_TIMING=0`** 이므로 동작 풀런은 **실시간 약 135분 + 헹굼 ~6분**이 걸린다(헹굼 구간은 애초에 압축 대상이 아니었다).
- 단계별로 나눠 볼 수단(양산 코드 그대로 유지되는 벤치 훅):
  - **헹굼 생략 → DJ_HEAT 직행**: `g_dongjak.dbg_enter_heat = 1`(배수문 닫힘 대기부터) / `= 2`(도어 대기까지 생략, 즉시 '가열중'). 앱 경로는 `PROTO_ACT_DJ_HEAT`(0x07)/`_ND`(0x08). `scn_start`가 now로 리셋되어 경과 0부터 카운트.
  - **마개 없이 시작**: `g_dongjak.dbg_force_start = 1`(lid 감시 미무장), 모드 고정은 `g_modearb.dbg_disable=1` + `g_app_mode=2`.
  - **타임라인 재압축이 필요하면** `dongjak.h`의 `DJ_TEST_FAST_TIMING`을 1로. → 110/120/130/135분이 7/8/9/12분, 1차 분쇄 30초, 배기팬 15초/2초 + 전환점 비프(7분대 삑/8분대 삑삑/9분대 삑삑삑). **양산 빌드에서는 반드시 0.**

### ★ 단계 전환 비프음은 **테스트용**이다 (양산 기능 아님)

동작 시나리오의 **단계 전환마다 울리는 스피커 비프는 순수 테스트 표식**이다. 벤치에서 사람이 계속
디버거를 안 보고도 "지금 몇 번째 구간에 들어갔는지"를 귀로 확인하려고 넣은 것으로, **기획서의 음성
안내(비움/배출완료/중단 멘트)와는 아무 관계가 없다.** 양산 동작에 이 소리가 나면 안 된다.

| 전환점 (양산 시각 / 압축 시각) | 비프 | 코드 |
|---|---|---|
| **110분** → 분쇄 2000 역회전 + 교반 27RPM (`DJ_T_HISPEED_MS`) / 압축 7분 | **삑** 1회 | `dongjak.c` DJ_HEAT tick, `test_beeped_hi` 래치로 1회만 |
| **120분** → 식힘 진입 `DJ_COOLDOWN` (`DJ_T_COOLDOWN_MS`) / 압축 8분 | **삑삑** 2회 | `dj_enter(DJ_COOLDOWN)` |
| **130분** → 배출 진입 `DJ_DISCHARGE` (`DJ_T_DISCHARGE_MS`) / 압축 9분 | **삑삑삑** 3회 | `dj_enter(DJ_DISCHARGE)` |
| (수동) 디버거에서 `g_dongjak.dbg_beep = N` | **N회** | 오디오 경로만 즉시 확인 |

> 참고: **135분**(`DJ_T_LATCH_MS`, 배출문 닫기 개시)에는 비프가 없다 — 배출 진입(130분)에서 3회를 울리고,
> 135분은 그 배출 창의 종료 시점이라 별도 표식을 두지 않았다. 필요하면 `dj_disch_begin_close()`에
> `dj_test_beep(4U)`를 추가하면 된다(`DJ_TEST_FAST_TIMING` 블록 안에서만).

- **구현**: `dj_test_beep()`는 `LM4871_Beep()` 기반 **블로킹**(busy-wait)이라 우는 동안 1ms `MotorTick`이 잠시 멈춘다. 테스트 한정으로 허용한 것이며, 이것만으로도 양산 코드에 남기면 안 되는 이유가 된다.
- **현재 상태**: `DJ_TEST_FAST_TIMING=0`이므로 **전부 컴파일 제외**(`dj_test_beep`·호출부 3곳·`dbg_beep`·`test_beeped_hi`·`lm4871.h` include). 소리 안 남.
- **완전 삭제 시**: `dongjak.h`의 `DJ_TEST_FAST_TIMING` 블록 + `dongjak.c`의 `[TEST]` 표시 코드를 함께 지운다.
- **단, 부팅 비프는 테스트용이 아니다**: `main.c`의 `LM4871_Beep(&lm4871, 2000, 120)`는 전원 인가 시 오디오 경로 확인용 기동음으로 별개 항목이다.

## 4. 권장 검증 순서

1. **도어 리밋홀 + 회전방향**(1-1·1-2) — 게이팅이 전 시퀀스의 진행 조건이라 여기가 막히면 통합 풀런 자체가 불가.
2. **NTC 실측 대조 + 히터**(1-4·1-3) — 건조 구간 전체가 이 두 개에 걸려 있다.
3. **HS7 수거통 소비 로직 구현**(1-9) — 안전 판정 공백.
4. **TIMER-OUT**(1-5) + **HW 인터록 확인**(1-6) — 배출 종료·고온 보호.
5. **통합 풀런**(1-11) — 위가 정리된 뒤 `DJ_TEST_FAST_TIMING=1`로 짧게 1회 → 0으로 실시간 1회.
6. 스테퍼 실부하(1-7) · DC 전류 정책(1-8) · HS6/HS8(1-10).
